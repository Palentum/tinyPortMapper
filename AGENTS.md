# Repository Guidelines

## Project Overview

tinyPortMapper (`tinymapper`) is a lightweight C++11 TCP/UDP port mapping and forwarding utility. It supports single-rule CLI startup and config-file startup with multiple forwarding rules in one process, forwarding IPv4, IPv6, and 4-to-6 / 6-to-4 traffic. The data plane is event-driven and embeds `libev` directly into the binary.

## Architecture & Data Flow

- `main.cpp` owns the application flow: CLI parsing, socket setup, libev watcher registration, signal handling, TCP/UDP callbacks, and connection cleanup.
- `process_arg()` parses single-rule CLI options (`-l`, `-r`, `-t`, `-u`) or `-c/--config <path>` into `app_config.rules`; log, color, socket-buffer (`--sock-buf`, `--udp-listen-buf`), `--disable-tcp-nodelay` and `--disable-splice` options remain process-wide.
- `event_loop()` creates the worker (`worker_new()`), materializes its `forward_rule_t` objects from `app_config`, creates only the enabled TCP/UDP listeners for each rule, registers `ev_io` accept/read watchers with `watcher->data` pointing at the owning rule, starts a periodic `ev_timer`, then calls `ev_run()`.
- Workers (M1, D59/D60): all per-worker mutable state lives in `worker_t`: its loop and time cache (`loop_clock_t clock`), the rule runtimes (`list<forward_rule_t> rules`: listen fds and watchers, the TCP/UDP managers with their LRUs, session tables and counters, `rr_nodes`, the remote address copies and, until M3, the DNS refresh state), the object pools (`tcp_pair_pool`, `udp_pair_pool`), `tcp_buf_pool` and `tcp_scratch`, `tcp_pipe_pool` and `tcp_pipe_scratch`, `udp_batch` and the `udp_flush_watcher`. Hot paths reach it through `forward_rule_t::worker` (pairs and sessions through `owner`, listener watchers through `data`, the prepare watcher's `data` is the worker); the managers keep `worker` for `erase()` and their `lru_collector_t` keeps `clock`. No `thread_local` (on mips24kc the TLS pointer is `rdhwr`, possibly emulated by the kernel) and no `ev_userdata()` (an out-of-line function in `ev.c`). `worker_new()` constructs the worker with placement new on anonymous `mmap` pages that are never freed, marked `MADV_NOHUGEPAGE` (with THP=always a huge page would make 2 MiB resident at once, at startup on kernels that 2 MiB-align large anonymous mappings, and khugepaged collapses such ranges too, which affected the BSS before; review L1): zero-filled and populated on demand, so `udp_batch`'s overflow areas stay non-resident until large datagrams land and the bytes no constructor writes (64-bit musl `msghdr` pads) stay 0; `new` does not guarantee zeroed memory and a `memset` would make all of it resident. While `threads=1` there is exactly one worker, on `ev_default_loop()` in the main thread (D59); `ev_loop_new()`, threads and the main/worker split come with M2/M3. The main thread reaches the workers only through the `workers` registry: `clear_timer_cb()` runs `worker_tick()` (LRU clearing, restarting stopped listener watchers, pipe-pool flag resets and regrow) for each worker, then the main-thread work (DNS scheduling for every rule, then `fflush`); DNS scheduling used to run per rule between clearing and restarting the watchers, which is not observable (it neither logs nor touches the pools); `sigusr1_cb()` runs `worker_stats()` per worker (identical output with one worker; the multi-worker format is for M3); DNS results are applied to every worker's rule copy by `dns_apply_result()`. Process-wide state that stays global: options and startup-computed values that are read-only afterwards (`tcp_pipe_size`, `splice_turn_max`, `tcp_pipe_min_size`, `tcp_pipe_max_free` (new pipe pools take it), `udp_gro`), learned flags that M2 turns into relaxed atomics (`disable_splice` set at run time, `udp_gso_hdr_cap`, the write-branch EAGAIN log-once, `udp_buf_force`, `udp_gro_listen()`'s `gro_socks`), and the logging caches and `get_str()`/`get_sock_error()` buffers that M2 makes `thread_local`.
- TCP flow: `tcp_accept_cb()` accepts the pending local clients of one `forward_rule_t`, calling `tcp_accept_one()` until `accept4(SOCK_NONBLOCK|SOCK_CLOEXEC)` returns EAGAIN (silently) or `max_accept_per_round` (8) clients were taken in this loop iteration (the listener must stay nonblocking, since the last `accept4()` of a round normally returns EAGAIN); any other accept failure and an immediate upstream `connect()` failure (EADDRNOTAVAIL first scans the whole ephemeral port range) also end the round, while `max_conn_num`, a failed connection-object allocation and an upstream `socket()` failure only drop that client and move on (if `accept4()` fails with anything but EAGAIN/EINTR/ECONNABORTED, e.g. EMFILE/ENFILE/ENOMEM or an LSM denial, the client stays in the backlog, so the rule's accept watcher is stopped and `clear_timer_cb()` restarts it on its next tick; an `EV_ERROR` on the accept watcher, e.g. a failed epoll re-add, is logged and retried the same way), takes a `tcp_pair_t` from `tcp_pair_pool` (if a new slab cannot be allocated, only that client is closed with a warn, before anything is sent to the upstream or the roundrobin index advances), opens a nonblocking remote socket to that rule's `remote_addr` (if `socket()` fails, e.g. EMFILE, only that client is closed and the pair goes back to the pool) and starts a nonblocking `connect()` (an immediate failure other than EINPROGRESS, e.g. ENETUNREACH or EADDRNOTAVAIL, closes the client with a warn), fills the `tcp_pair_t` with both fds and points both watchers' `data` at it, then `tcp_cb()` relays data between the two endpoints while toggling `EV_READ` / `EV_WRITE` watchers for backpressure. Every `recv()` reads up to `max_data_len_tcp` (64 KiB) into the worker's `tcp_scratch` block; if `send()` takes all of it the block stays scratch for the next `recv()`, otherwise (partial or failed send, or upstream still connecting; a send error is left to the write branch, which closes the pair) the block itself is handed to that direction (`tcp_info_t::buf`, with `begin`/`data_len`; no copy), reading from the source stops, and the next `recv()` first takes another block from `tcp_buf_pool`. A direction holds a block only while it has unsent data (`buf` is non-null exactly when `data_len` is non-zero): the write branch returns it once drained, and the managers return held blocks when they release a pair. The pool keeps at most `tcp_buf_pool_max_free` (64) free blocks and `free()`s the rest; an empty pool `malloc()`s a new block. If that `malloc()` fails (only under `RLIMIT_DATA`/`RLIMIT_AS` or `vm.overcommit_memory=2`; with default overcommit, exhaustion means the OOM killer), the pair whose `recv()` needed the block is closed with a warn: whichever pair reads next, not necessarily the one holding memory, and the read branch runs first even when that side could have drained its own held block by writing. Other allocation failures still abort the process: libev growing its fd array for a new fd peak (`ev_realloc`), the DNS thread's queues. User-space memory therefore follows backpressure: an idle pair is about 0.3 KB, but each direction whose destination is slower than its source holds a whole 64 KiB block until it drains (at most 2 × 64 KiB per pair, with no global cap besides `max_conn_num`). Bulk directions bypass user space with splice (B1/B2, D46–D48): each direction remembers whether its last successful read (recv or splice) returned at least `splice_read_min` (16 KiB) (`tcp_info_t::splice_next`, recomputed after every read, not sticky, so small-message traffic never splices: a 64-byte splice costs about 4% more than recv+send, a 16 KiB one 19% less). If it did, the other side is connected and `--disable-splice` was not given, the read is `splice(src → tcp_pipe_scratch, tcp_pipe_size, SPLICE_F_MOVE|SPLICE_F_NONBLOCK)` and the data leaves through `splice(pipe → dst)` after `nodelay_before_send()` (no `SPLICE_F_MORE`: the kernel adds `MSG_MORE` itself between the pipe buffers of one call). `tcp_pipe_size` (B3: `--pipe-size` in KiB, 64–1024, default 256 KiB, D55/D57) is both the size new pipes are grown to and the most one splice reads, so it bounds what a waiting direction holds in a pipe; pipe contents are kernel pages charged to neither `tcp_mem` nor the memcg (D51 had 64 KiB). Since 5.5 (backported to 4.19.y and 5.4.y) the kernel caps a splice into a pipe at its free slots × PAGE_SIZE; 4.9.y/4.14.y do not, so there a 16-slot pipe can take sixteen 32 KiB local fragments. Every skb fragment takes one slot: local senders (loopback, veth) produce 32 KiB fragments, a NIC after GRO about one MSS each, so a 16-slot (64 KiB) pipe moves about 22 KiB per splice from a NIC and a 64-slot (256 KiB) one about 90 KB (B12 review M3; the Docker bench cannot show this). While each splice-in returns at least `splice_more_min` (64 KiB) and the splice-out writes all of it, the callback reads again, requesting `min(tcp_pipe_size, splice_turn_max - moved)`, until it has moved `splice_turn_max` bytes (D53/D55/D56): 256 KiB, or (size / 256 KiB) × size above 256 KiB (1 MiB at 512, 4 MiB at 1024); `--pipe-size 64` is exactly the B2 behavior (4 × 64 KiB). Measured with 8 loopback streams on one forwarder CPU plus a same-process 64-byte round trip: 64 KiB × 4 reads 115 Gbit/s and p50 295 µs, 256 KiB × 1 161 Gbit/s and 216 µs (part of that gain is a loopback artifact: a 65536-byte splice-out is one 65483-byte MSS segment plus a 53-byte tail), 256 KiB × 4 173 Gbit/s but 774 µs; 1 MiB × 4 207–213 Gbit/s with p99 2.8 ms, like realm `-p 256` (experiment variants; the B3 formal batch with the real build: default 159.8 Gbit/s, p50/p99 220/328 µs; `--pipe-size 1024` 204.3 Gbit/s, p50/p90/p99 201/2,579/2,923 µs; realm `-p 256` 214.1, 139/958/2,624). In later reads an EOF or EAGAIN ends the loop and the next callback handles it as its first round (EOF stays readable), but any other error closes the pair at once: splice has already consumed `sk_err`, so the next read would return 0 and an RST would be forwarded as a clean EOF. The pipe is handled like the scratch block (D47): written out completely, it stays the scratch pipe; otherwise (partial write, EAGAIN, or an error left to the write branch) the pipe with its data goes to the direction (`tcp_info_t::pipe`; `data_len` counts the unsent bytes in either the block or the pipe, never both, and `data_len != 0` exactly when one of them is held), reading the source stops, and the write branch drains it with splice and returns it to `tcp_pipe_pool` (free pipes kept up to `tcp_pipe_pool_t::max_free`, the rest closed: 1024 pages in total, 64 × 16 / slots per pipe, so 64 at 64 KiB, 16 at 256 KiB, 4 at 1 MiB, because the uid's pipe quota counts idle pipes too and a count cap of 64 would let `--pipe-size 1024` keep the whole default soft limit, review M1; `free_pipes[]` stays sized `tcp_pipe_pool_max_free` (64); while `quota_hit` is set, i.e. after `create()` got a pipe of fewer than 16 slots and until `clear_timer_cb()`'s next tick, which then trims the free list back to `max_free`, `put()` keeps up to 64, because during that `blocked` window drained pipes are reused at once and closing them sent directions to recv (re-review R1: non-root 2000 stalled connections at `--pipe-size 1024` 63.4 → 73.2 Gbit/s, default unchanged; fd shortage does not set it and `tcp_pipe_trim()` clears it, D52; free pipes can then hold 130 fds, as before review M1). After every partial splice-out (the hand-off above and a partial write in the write branch) `tcp_unshrink_sndbuf()` checks the destination (D54): when the host is under `tcp_mem` pressure the kernel shrinks an unlocked sndbuf to half its queue (`sk_stream_moderate_sndbuf`) and does not grow it back while the pressure lasts; with a loopback-class MSS (65483) that leaves one segment in flight and the receiver delays its ACK (~40 ms), which halved splice throughput with 2000 stalled loopback connections (the copy path rarely gets shrunk; why the zero-copy chain does is not known). So if `SO_SNDBUF` < 2 × `TCP_MAXSEG` it sets `SO_SNDBUF` to 2 × MSS (the kernel doubles it to four segments, 256 KiB on loopback, and locks it, so that socket no longer autotunes); the MSS is read once per direction into `tcp_info_t::mss` (0 unread, -1 on failure) and while 2 × MSS ≤ `tcp_min_sndbuf` (4608, `SOCK_MIN_SNDBUF`), e.g. any MSS 1448 path, the function returns at once from then on (the smallest sndbuf already holds three such segments; gating on the sndbuf alone would lock new WAN connections, whose sndbuf starts near 87 KB); otherwise it costs one `SO_SNDBUF` `getsockopt()` per partial write, and nothing with `--sock-buf`. A `net.core.wmem_max` below ~17 KiB would clamp the lock below the shrunk size (recorded, not handled); with `net.ipv4.tcp_wmem[2]` below two loopback segments the lock also applies without memory pressure and exceeds that cap. A held pipe always contains data, so releasing a pair closes it (`tcp_pipe_pool_t::discard()`): a pipe with data is never reused, which would send one connection's bytes to another. An empty pool creates a pipe out of line (`tcp_pipe_pool_t::create()`): `pipe2(O_NONBLOCK|O_CLOEXEC)`; a pipe whose higher fd is at or above three quarters of the `RLIMIT_NOFILE` soft limit (read with `getrlimit()` at each creation) is closed (D52: the last quarter of the descriptors is for sockets, since a backpressured direction holds a pipe and a pair can then use 6 fds instead of 2); then `F_GETPIPE_SZ`, and a pipe with fewer than 16 slots (`tcp_pipe_min_size`, 16 pages, D58; counting bytes would let a 2-page 128 KiB pipe through on 64K-page kernels) is closed (a user without `CAP_SYS_RESOURCE`/`CAP_SYS_ADMIN` in the initial user namespace whose pipes together reach `fs.pipe-user-pages-soft` gets 2 pages; container root with Docker's default capabilities is such a user, and uid 0 is shared by every root process of the host; the count is by capacity, so free pooled pipes count too: 1024 pipes of 64 KiB, 256 of 256 KiB, 64 of 1 MiB). A pipe smaller than `tcp_pipe_size` is then grown with `F_SETPIPE_SZ` (never shrunk: on 64K-page kernels the default 16 slots are already 1 MiB). If growing fails (EPERM from that quota, ENOMEM), the pipe keeps its size and is used anyway (D58): `tcp_pipe_pool.resize_fail` counts it, `grow_blocked` skips further attempts (still counted) until `clear_timer_cb()`'s next tick, and the first failure per worker (per process while `threads=1`) logs info, later ones debug (the level is computed before `mylog()`, whose macro evaluates its level argument twice). A pipe that could not be grown would otherwise stay the scratch pipe and cycle through the pool for good (review M2), so once `resize_fail` is non-zero `clear_timer_cb()` calls `tcp_pipe_pool_t::regrow()` on the scratch pipe every tick (`F_GETPIPE_SZ`, and `F_SETPIPE_SZ` if smaller; a failure sets `grow_blocked`, not counted, not logged); small pooled pipes get regrown when they become the scratch pipe. Before the event loop, unless `--disable-splice` was given, `tcp_pipe_probe()` sets `tcp_pipe_min_size` from the page size, rounds `tcp_pipe_size` up to a power of two pages as the kernel will (300 → 512 KiB; done in user space so that reads and `splice_turn_max` match the pipes even if the probe cannot set the size, review L2), creates one pipe and tries `F_SETPIPE_SZ(tcp_pipe_size)`: success takes the returned size, and EPERM with a request above `/proc/sys/fs/pipe-max-size` (no `CAP_SYS_RESOURCE`) uses pipe-max-size with a warn if `--pipe-size` was given (`pipe_size_explicit`) and an info line for the default (as D40); other failures (quota already full) are left to `create()`, and an unreadable `/proc/sys` with a lowered pipe-max-size is not handled (every new pipe then fails to grow, review L3). It then sets `splice_turn_max` and `tcp_pipe_max_free`, which every worker's pipe pool takes as `max_free` when it is constructed (the probe runs before `worker_new()`). Any failure (also EMFILE/ENFILE) makes that read use recv, adds 1 to the rule's `splice_fallback`, logs the reason (info the first time per worker, i.e. per process while `threads=1`, debug afterwards) and sets `tcp_pipe_pool.blocked`, so no creation is tried until `clear_timer_cb()` clears it on its next tick. When `accept4()` or the upstream `socket()` fails with EMFILE/ENFILE, `tcp_accept_one()` calls `tcp_pipe_trim()`, which closes every free pooled pipe and the scratch pipe and sets `blocked` (held pipes contain data and stay). A splice read that fails with ENOSYS, EPERM, EINVAL or EOPNOTSUPP (splice itself unavailable, e.g. a seccomp allow-list without it; nothing was read) logs one warn, sets `disable_splice` for the rest of the process and reads with recv instead. A splice read that returns EAGAIN is retried once with `recv()`: with TCP urgent data (`MSG_OOB`) at the head of the receive queue a nonblocking `tcp_splice_read()` returns EAGAIN while `tcp_poll()` keeps reporting readable (the urgent byte does not count), so without the retry the pair would spin; `recv()` skips the urgent byte (no `SO_OOBINLINE`) as the copy path always did. A splice read of 0 is EOF and other errors close the pair, exactly like recv; a splice write to a reset peer raises SIGPIPE like `send(…, 0)` (libev's `sigpipe_cb` logs it). While the upstream is CONNECTING only recv is used. Assert builds check with `FIONREAD` (`tcp_pipe_len()`) that the scratch pipe is empty before a splice read and that a pipe is empty when it goes back to the pool. Pooled pipes keep up to `2 × (max_free + 1)` fds open (34 by default, 130 with `--pipe-size 64` or while `quota_hit` is set) after the connections that used them are gone. Both sides run with `TCP_NODELAY` unless `--disable-tcp-nodelay` is given: the TCP listener sets it once and accepted sockets inherit it; the upstream socket gets it from `nodelay_before_send()` right before its second `send()` (T15, `tcp_info_t::nodelay_wait`), or before the first one if that is larger than `nodelay_first_max` (536 bytes, `TCP_MSS_DEFAULT`). Linux's Nagle (Minshall variant) holds a sub-MSS segment only while an earlier small segment is unacknowledged, and a first write of at most 536 bytes is never cut into a small segment at a window edge that is not MSS-aligned (a larger one can be, e.g. a backend with an 8 KiB receive buffer advertises 7240 bytes while the path MSS is 1388, and its tail then waits for that segment's ACK; measured as rare, see `docs/tasks/p1.md` T15), so a connection that writes the upstream once (CRR, a small RPC request) saves the `setsockopt`. Every `send()` in `tcp_cb()` must go through `nodelay_before_send()` first (the client side's `nodelay_wait` is always 0). The TCP listener calls `listen()` with `listen_backlog` (65535), which the kernel caps at `net.core.somaxconn` (4096 by default since Linux 5.4, 128 before); the libc `SOMAXCONN` macro is not used because musl (and glibc before 2.31) define it as 128. TCP socket buffers are left to kernel autotuning: `SO_SNDBUF`/`SO_RCVBUF` are set only when `--sock-buf` is given (`sock_buf_explicit`), then once on the TCP listener before `listen()` (accepted sockets inherit the size and the `SOCK_*BUF_LOCK` bits, so setting it on the listener unconditionally would disable autotuning for every client) and on the upstream socket before `connect()`. Connect state: while the upstream is CONNECTING (`tcp_info_t::connected==0`) its watcher waits for `EV_READ|EV_WRITE` and nothing is sent or shut down on it; a writable-only report means connected, a readable report is checked with `getsockopt(SO_ERROR)`, and an error (refused, unreachable, or the kernel's SYN timeout ETIMEDOUT; there is no separate connect timer, only the TCP idle timeout) closes the pair with a warn. Client data read meanwhile (one 64 KiB block) is held and sent once the upstream connects, before anything is read from the upstream. Half-close: an EOF from one side (`tcp_info_t::eof`) is forwarded as `shutdown(SHUT_WR)` on the other side while the opposite direction keeps flowing; if the upstream is still connecting the shutdown waits until it connects, because `shutdown()` on a SYN_SENT socket aborts the connect. The pair is released once both sides have sent EOF, or on any recv/send/shutdown error (except EAGAIN from the write branch's send or splice, D50: EPOLLOUT only reflects the socket's own free space, and when the host is above `tcp_mem[2]` or a memcg charge fails, a socket with a nearly empty queue still gets EAGAIN, so the write branch keeps `EV_WRITE` and retries on the next loop iteration; with an unlocked sndbuf the kernel shrinks it first, so only such near-empty queues, or `--sock-buf` sockets, can spin until memory recovers), or when one of its watchers gets `EV_ERROR` (libev's `fd_kill` after `epoll_ctl` fails with anything but ENOENT/EEXIST/EPERM, in practice an `EPOLL_CTL_ADD` beyond `fs.epoll.max_user_watches` (ENOSPC) or ENOMEM, for a new fd or for an established pair's fd that libev deleted from epoll while backpressure had dropped its event mask to 0 and now re-adds; libev has already stopped that watcher): a warn, and only that pair is released.
- UDP flow: `udp_accept_cb()` reads the listen socket with `recvmmsg()` into its worker's `udp_batch` (U1, D34; one per worker since M1): up to `udp_batch_max` (64) datagrams per call, each into two iovecs, a 2 KiB slot (the 64 slots are contiguous) and that message's own overflow area, `max_data_len_udp` (65536) bytes in all, so MTU-sized packets touch only the slots and the ~4 MiB of overflow area becomes resident only where datagrams larger than 2 KiB land; `MSG_TRUNC` (a datagram larger than 65536) drops the packet with the `huge packet` warn. It makes one `recvmmsg()` call per callback (D35): level-triggered epoll reports the fd again in the next iteration for whatever is left, so the inbound path takes at most 64 packets of a loop iteration and other watchers (TCP, the return path) wait for at most one batch; an EAGAIN (the packet that woke the loop failed its checksum and was dropped) is not logged, other errors are logged at debug. `udp_forward_batch()` restores `msg_namelen` of every received entry (the kernel overwrites it with the address length) and looks every packet's client address up with `conn_manager_udp_t::find()`: first `last_hit` (the session the previous lookup returned; `erase()` clears it, because a released pair keeps its old address and the LIFO pool hands it to the next session, so every release of a UDP session must go through `conn_manager_udp_t::erase()`), then `sessions`, a `udp_table_t` (U2): open addressing with linear probing, a power-of-two capacity that starts at 64 slots, doubles when an insert would exceed 3/4 and never shrinks (at most 32768 slots for `max_conn_num`), slots holding the session pointer and the key's 32-bit hash (probes compare the hash before touching another session; growth re-places entries by the stored hash), backward-shift deletion without tombstones. The key is family, port and address, plus `sin6_scope_id` for IPv6 (`udp_key_eq()`; `sin6_flowinfo` is always 0 from the kernel, so this equals comparing the whole `address_t`), hashed with `fmix64` once per 64-bit word (`udp_key_hash()`, unseeded). The first packet from a new address creates the session in `udp_new_session()`, which makes room in the table first (if that `malloc()` fails, only the packet is dropped, with the same info line as a slab failure, before the roundrobin index advances), creates one connected UDP socket to that rule's `remote_addr` and takes a `udp_pair_t` from `udp_pair_pool` (if a new slab cannot be allocated, the socket is closed and the packet dropped with an info line), stores it in the rule's `conn_manager_udp`. Then the batch is grouped by session (U3): `udp_pair_t::batch_group` is the session's group index while a batch is being forwarded and -1 otherwise (`conn_manager_udp_t::erase()` asserts it; nothing in `udp_forward_batch()` releases a session), a counting sort lays out each session's packets contiguously in `udp_batch.out` in arrival order, and the groups go out in the order of their session's first packet, after one `lru.update()` per group, each with one `sendmmsg` on the session's connected socket (`msg_name` stays 0: an address on a connected UDP socket would redirect the datagram there). `udp_send_group()` calls `syscall(SYS_sendmmsg, ...)` directly: on 64-bit musl `sendmmsg()` is a loop of `sendmsg()` calls, because musl's `msghdr` has `int` fields plus `__pad1`/`__pad2` where the kernel has `size_t`; the raw syscall is correct only while those pads are 0, which holds because `udp_batch` lies in the zero-filled `mmap` pages of `worker_new()` (zero-initialized BSS before M1) and nothing writes them (musl's `recvmmsg()` is the real syscall and zeroes them itself). A partial `sendmmsg()` continues from where it stopped (the kernel does not report the error of the message that stopped it, so the retry finds out whether it still fails); EAGAIN drops the rest of that session's group, any other error (EMSGSIZE) only the message at that point. An ICMP error (ECONNREFUSED) caused by an earlier packet makes the send at the break point fail and is consumed by it, so the retry succeeds: only an error hit by the first packet of a group drops a packet and logs (the earlier per-packet `send()` dropped one every time); each failed call adds the dropped packets to `drop[0]` and logs one warn with their count. The return path (U4, D36) batches across sessions: `udp_cb()` (a session socket is readable) makes one `recvmmsg()` per callback into the free part of the return batch, which shares `udp_batch`'s slots and overflow areas (entries `rin`/`raddr`/`rrule`, occupying `slot[0..rn)`), at most `udp_return_quota` (16, D37) and never more than what is left of the 64 entries, so a session takes at most 16 replies per loop iteration and leaves the rest to level-triggered epoll (the inbound path takes up to 64 per listen socket per iteration, but one listen socket carries every client while each session has its own socket: with a per-session quota of 64, a forwarder slower than its senders spent each iteration on backlogged sessions and the inbound path got about 1/6 of the packets, measured with the forwarder on a third of a CPU: inbound 134 kpps before U4, 82 with 64, 130 with 16, and same-process TCP round trips p50 315 µs, 586, 335; the price of 16 is about −11% on many-session reverse floods at full CPU, `docs/tasks/p2.md`); each packet's client address is copied into `raddr` (defensive: with libev's callback order no release path can run between a session's `udp_cb()` and the next flush, since timers, the DNS async and signals are invoked before the iteration's I/O callbacks and an `EV_ERROR` only hits a session never registered with epoll; the copy keeps a future release path from redirecting a pending reply to whichever client gets the pooled object next), its rule into `rrule` (`MSG_TRUNC` drops it with the `huge packet` warn), and the session's LRU entry is refreshed once per callback. `udp_flush_return()` sends the batch grouped by rule (in order of each rule's first packet, arrival order inside), one `sendmmsg()` per rule on that rule's listen socket through `udp_send_group(..., 1)` (`rout`, whose musl pads must stay 0 like `out`), with the same partial-send/EAGAIN/one-drop semantics as inbound and the warn `[udp]sendmmsg to clients returned ...` (the listen socket is not connected, so no ICMP errors show up there; failures are e.g. EMSGSIZE for a 65527-byte IPv6 reply to an IPv4 client, or EAGAIN when its send buffer is full: 2×`listen_fd_buf_size`, 4 MiB by default with `CAP_NET_ADMIN`, otherwise 2×min(`listen_fd_buf_size`, `wmem_max`), 416 KiB before Linux 6.18; never on loopback, whose xmit orphans the skb, so tests inject it with seccomp). It runs when the batch is full, at the start of `udp_accept_cb()` before the inbound `recvmmsg()` reuses the slots (anything else that writes the slots must flush first), and from an `ev_prepare` watcher (`udp_flush_cb()`, started only if some rule enables UDP) right before libev blocks in `epoll_wait`, so a reply never waits past the loop iteration it arrived in. Not `ev_check`: libev invokes the pending watchers of one priority in reverse order of queueing (`ev_invoke_pending`), and check watchers are queued last, so a default-priority check watcher runs before the iteration's I/O callbacks. A receive error other than EAGAIN (e.g. ECONNREFUSED from an ICMP port unreachable) is logged as `[udp]recv failed`; EAGAIN is silent. An `EV_ERROR` on a session watcher logs a warn and releases only that session (the client's next packet creates a new one); on a UDP listener it is logged and `clear_timer_cb()` restarts the watcher on its next tick, like the TCP accept watcher. With `--udp-gro` (U5, D41–D43; process-wide, command line only, off by default) every UDP listen and session socket gets `UDP_GRO` (`udp_gro_set()`): the kernel merges a burst of one flow arriving through a GRO-capable interface into one buffer and reports the segment size in a `SOL_UDP`/`UDP_GRO` cmsg (an `int`: read as u16 it is 0 on big-endian MIPS). `udp_gro_listen()` attaches the control buffers `udp_batch.ctrl[i]` to `in[i]` and `rin[i]` (shared by both like the slots) whenever one of that worker's listen sockets accepts the option (idempotent); if the first one fails (kernel before 5.0) it warns and clears `udp_gro`, so no socket ever has `UDP_GRO` while cmsgs are not parsed (a merged buffer would otherwise go out as one oversized datagram); later failures only log (debug for a session socket). `udp_recv_gso()` walks the cmsgs, copies the size into `gso[i]` and restores `msg_controllen` for every received entry (needed before the next `recvmmsg`); an entry with `MSG_CTRUNC` is dropped with a warn (review L4: the kernel writes `SO_TIMESTAMP`-like cmsgs before `UDP_GRO`, and reading a merged buffer as one datagram would forward it whole; enlarge `udp_ctrl_t` if such options are ever enabled). `udp_batch_set_gso()` gives the matching send entry (`out_ctrl`/`rout_ctrl`) a `UDP_SEGMENT` cmsg (`cmsg_len` must be exactly `CMSG_LEN(sizeof(u16))`) only when the packet has more than one segment (without TX checksum offload, kernels before 6.11 return EIO even for one segment), so a merged packet is one `sendmmsg` entry that the kernel or the NIC splits into the original datagrams. `udp_send_group()` takes a `udp_send_ctx_t` and passes entries that `sendmmsg` must not get (GSO is off for that session and direction, or more than `udp_gso_cap()` segments: `udp_gso_max_segs` (64), since `UDP_MAX_SEGMENTS` is 64 before 6.9, 128 since and in Ubuntu's 6.8) and failed GSO entries to `udp_send_split()`, which sends one merged packet in pieces of at most that many segments, or datagram by datagram once GSO is off, through `udp_batch.seg` (musl pads must stay 0, like `out`). The fallback state is per session and direction (D45, `udp_pair_t::gso_off[2]`): inbound the context points at the session's `gso_off[0]` for the whole group; on the return path `udp_cb()` copies the session's `gso_off[1]` into `roff[slot]` and the flush into `rout_off[entry]` (no session pointer is kept, D36), because the listen socket checks each client's own route PMTU. EIO, EINVAL or EMSGSIZE on a GSO entry (no TX checksum offload before 6.11, or IPsec; a segment larger than the path MTU: EINVAL up to 6.13, EMSGSIZE since 6.14 and in Ubuntu's 6.8; too many segments) call `udp_gso_turn_off()`: it sets the flag (return path: the session is found again by the client address that `msg_name` points to, `raddr[j].inner` being `address_t`'s only data member, and the group's later entries to that client are switched too), adds 1 to `gso_fallback[dir]`, logs `[udp]GSO send from|to {client} on session|listen fd N failed (...)` at info for the first time per rule and direction and at debug after that (review L3), and the packet is resent datagram by datagram. An EINVAL on more than 64−⌈48/gso⌉ segments is first taken as the old-kernel limit (5.0–5.15 without the v5.16 fix count the IP/UDP headers, so 64 full segments always fail; review L1): `udp_gso_old_limit()` sets the process-wide `udp_gso_hdr_cap` and the packet is resent in smaller pieces without turning GSO off. Any other error (e.g. an ICMP error, consumed by that call) sends the packet once more as GSO and drops a piece that fails again; EAGAIN drops the rest of the group as before. With `--udp-gro`, `new_connected_udp_fd()` sets a session's SO_SNDBUF to `listen_fd_buf_size` when that is larger than `socket_buf_size`, past the cap when it can (D44): one inbound callback can hand a session everything queued on the listen socket (up to 64 merged packets, ~4 MiB), and a real NIC releases send-buffer memory only after transmission, so a smaller sndbuf turned bursts the listen buffer absorbs into EAGAIN drops (measured with a tbf qdisc holding the skbs; veth and lo orphan them at once); the cost is up to that much data queued per overloaded session in the egress qdisc (send-side memory is not in `udp_mem`). The batch limits (D35, D37) count entries, so with merged packets one loop pass can move ~4 MiB each way (review L5). `pkts`, `bytes` and `drop` count datagrams, `gro[dir]` the datagrams that arrived merged. Side effects: `UDP_GRO` on any socket turns on the kernel's `udp_encap_needed_key`, so every UDP packet the host receives gets a socket lookup in the GRO stage; merged packets use the overflow areas, so GRO traffic makes the ~4 MiB of overflow area resident. loopback never merges plain datagrams; only local GSO sends pass lo whole (since 5.11), which is how the tests produce merged packets. UDP sockets always get explicit buffers (U6, D38–D40): the listener `listen_fd_buf_size` (2 MiB, or `--udp-listen-buf`) through `set_udp_buf_size()`, each session `socket_buf_size` (1 MiB, or `--sock-buf`), per direction through `set_udp_buf_dir()` in `new_connected_udp_fd()`, forced only when `sock_buf_explicit` (with `--udp-gro` the send side may take `listen_fd_buf_size`, D44) (D38 revised: forced session buffers multiply with the session count; with 2 MiB sessions a 32-flow reverse flood lost 13% throughput and queued 28 ms instead of 0.55 ms, and on a 128 MB router a few full queues reach `net.ipv4.udp_mem[0]`, UDP's effective global receive limit, about 11 MiB there). `set_udp_buf_size()` tries `SO_SNDBUFFORCE`/`SO_RCVBUFFORCE` first, which need `CAP_NET_ADMIN` in the initial user namespace (the kernel checks `capable()`: root on the host has it, root in a user namespace does not) and are not capped by `net.core.rmem_max`/`wmem_max`; the first failure (EPERM) is logged at debug and remembered in the file-scope `udp_buf_force` (shared by both directions through `set_udp_buf_dir()`), so later UDP sockets use the plain options directly and a process without the capability spends no extra syscall per session (a racy but monotonic flag; P4 workers need a startup probe or an atomic). A later plain `SO_RCVBUF`/`SO_SNDBUF` on a forced socket would shrink it back to the capped size, so re-set UDP buffers only through `set_udp_buf_size()`/`set_udp_buf_dir()`. The kernel stores twice the request, capped first by `rmem_max`/`wmem_max` (212992 before Linux 6.18, 4 MiB since) when not forced: without the capability on an untuned older kernel both kinds of socket get 416 KiB; with it the listener gets 4 MiB per direction (what 6.18+ gives anyway) and sessions keep 416 KiB unless `--sock-buf` is given. After setting the listener's buffers `start_forward_rule()` reads both back and logs one info line per UDP rule when either is below twice the request. TCP sockets never use the FORCE options.
- Connection lifetime is LRU-based per rule. Each `forward_rule_t` owns `conn_manager_tcp_t`, `conn_manager_udp_t`, and their `lru_collector_t` state; `clear_timer_cb()` periodically removes inactive pairs across all rules. Time comes from the worker's `loop_clock_t::now()` (ms; `lru_collector_t::clock` points at it): libev's monotonic clock as cached for the current loop iteration (`my_ev_mono_now()` reads that loop's `mn_now`, which libev refreshes from `CLOCK_MONOTONIC` after every `epoll_wait`), so nothing reads the clock per event and wall-clock steps (NTP, `date -s`) do not change idle timeouts; the ms value is cached (`last_bits`/`last_ms`, per worker) by the bit pattern of `mn_now`, so soft-float targets (mips24kc, arm) do the double conversion once per iteration. Call it only on the thread that runs that loop. `lru_collector_t` is an intrusive doubly linked list: `tcp_pair_t`/`udp_pair_t` inherit `lru_node_t` (`prev`/`next`/`ts`), so linking, moving and unlinking allocate nothing and need no lookup. Pairs come from `obj_pool_t` (`tcp_pair_pool`, `udp_pair_pool`): slabs of 64 objects that are never freed and a LIFO free list; `get()` constructs the object in place, so a reused pair starts with null LRU links, zeroed watchers and no buffers. A pair is linked by `lru.new_key()` right after `get()` and unlinked only in the managers' `erase()`/`erase_closed()`, before `put()` returns it to the pool. The LRU list is the only list of a manager's pairs: `clear_remote_index()` walks it (taking `next` before releasing the current pair), and `lru.size()` is the connection count used in logs and for `max_conn_num`. The collector's sentinel `head` points to itself, so its copy operations are deleted: it cannot live in a container that relocates elements (e.g. a growing `vector`). `lru_collector_t::update()` moves a pair to the front only when its timestamp is at least `lru_move_interval` (1 s) old, so a pair can be cleared up to 1 s before its exact idle timeout.
- Watchers reach their owner through `watcher->data` (`EV_COMMON` in `my_ev_common.h` is only `void *data;`): the `forward_rule_t` for the listener watchers, the `tcp_pair_t` for both watchers of a TCP pair (`tcp_cb()` tells the side by comparing `watcher` with `&pair.local.ev`), the `udp_pair_t` for a UDP session; fds are plain `int`s (`tcp_info_t::fd`, `udp_pair_t::fd`), with no lookup table. The managers' `erase()`/`erase_closed()` release a pair in a fixed order: `ev_io_stop()` each of its watchers, then `close()` its fds, then return its buffers and the pair to the pools. `ev_io_stop()` also discards the watcher's event still pending in the current loop iteration, so no callback can reach a released pair, and a later callback of the same iteration may reuse the fd numbers (e.g. `accept4()`) and, because the pool is LIFO, normally the pair's memory too. Do not return a pair to the pool, or start reusing its memory, before both watchers are stopped; `obj_pool_t::put()` checks this in every build, including release (X1, D30): if a watcher of the returned pair is still active or pending it logs `log_fatal` and calls `abort()` (four field reads and one branch per release). libev's own `corrupted watcher` assertion only catches a watcher list that loops onto itself, not longer loops or a stale watcher on another fd number. In ASan builds (`__SANITIZE_ADDRESS__`) free pool objects and blocks are poisoned, so a callback reaching a released pair is reported unless the pair was already reused, which is the common case for a missing `ev_io_stop()`: the next `accept4()` of the same iteration usually gets the pair back and libev's `corrupted watcher` assertion fires instead (keep `assert()` enabled in test builds, and `DEBUG_ASSERT` too: `make test` runs the `-assert` builds). A watcher that gets a new fd must go through `ev_io_init()` (or `ev_io_set()`): its `EV__IOFDSET` flag makes libev re-register the fd with epoll even when the same fd number was closed earlier in this iteration with the same event mask (libev still caches the old mask), and with the local `fd_reify` patch (T13) the fd is ADDed directly instead of MOD (ENOENT) then ADD. Event changes on the fd a watcher already has must not go through `ev_io_init()`: `tcp_cb()` stops the watcher, changes `events` and restarts it; an `ev_io_init()` on a still-registered fd would cost an ADD (EEXIST) plus a MOD.
- Counters (O1, D25–D27): SIGUSR1 (an `ev_signal` started in `main()`; earlier versions exited on it) runs `sigusr1_cb()`, which calls `worker_stats()` for each worker (one while `threads=1`): it writes, for each rule, a `stats rule N tcp:` and/or `udp:` line and then one `stats pool:` line for that worker's pools with `mylog_unfiltered` (written at every `--log-level` except 0), then `fflush`es stdout. Only cumulative counters are updated on the hot path: `conn_manager_tcp_t::total`/`bytes[2]`/`splice_bytes[2]` (the part of `bytes` written from a pipe)/`splice_fallback` (reads that wanted a pipe but got none, D49) and `conn_manager_udp_t::total`/`pkts[2]`/`bytes[2]`/`drop[2]` (index 0 client→upstream, 1 upstream→client; bytes and packets are counted per datagram that `sendmmsg()` sent, `drop` per datagram a failed call dropped, any errno (an EAGAIN drops the rest of the group: inbound the session's batch, U3; on the return path the rule's part of the return batch, U4; return-path counters change when the batch is flushed, at the latest before the loop blocks); `total` is incremented next to `lru.new_key()`), plus `tcp_buf_pool_t::alloc`, `tcp_pipe_pool_t::alloc` and `obj_pool_t::slabs`, which change only on the pools' `malloc()`/`free()` or a pipe's creation and close. The `tcp:` line ends with `up_splice`/`down_splice`/`splice_fallback`, the `stats pool:` line with `pipes alloc/held/free/scratch resize_fail` (both appended; `resize_fail` was added after them by B3, so older positional parsers still read the leading fields). With `--udp-gro` (D42, only then) the `udp:` line ends with `up_gro`/`down_gro` (`conn_manager_udp_t::gro[2]`, datagrams that arrived merged, counted at receive after the `MSG_TRUNC` check) and `up_gso_fallback`/`down_gso_fallback` (`gso_fallback[2]`, sessions that turned GSO off in that direction); without it the line is unchanged. Current connections come from `lru.size()`; half-closed pairs (`local.eof||remote.eof`) and blocks held by directions are counted when the signal arrives, by walking each rule's LRU (about 55 ns per pair with cold caches, 1–2 ms for 20000 pairs). libev runs the callback between other callbacks (the signal handler only marks the signal pending and wakes the loop through the eventfd), where `alloc == held + free + scratch` for both the blocks and the pipes, each object pool's `slabs*64 - free` equals the pairs in all of its worker's rules' LRUs, and each rule's `sessions.cnt` equals its UDP `lru.size()`; it `DEBUG_ASSERT`s these only after flushing the lines, so a violation leaves the numbers in the log. Put a new counter in the per-rule manager (the managers belong to the worker's rule runtimes).

- `libev/`: Vendored libev snapshot and compatibility files. `.gitattributes` marks this directory as vendored. Maintenance scripts live here too. The snapshot is libev 4.24 plus later CVS changes (`libev/Changes` rev 1.315), with two local patches that affect Linux builds. T13 (D24): `fd_reify()` in `libev/ev.c` passes old mask 0 to the backend for an fd whose watcher was (re)set with `ev_io_set()` (`EV__IOFDSET`) in this iteration, so epoll ADDs it directly; upstream sends MOD first when the fd number was closed and reused in the same iteration (the cached mask is the old fd's), which fails with ENOENT before the ADD. The patch is only valid for epoll: poll/select, kqueue, port and libev ≥ 4.31's io_uring use the old mask to remove the old registration. `my_ev.cpp` fails the build if the patch marker `TPM_LIBEV_FD_REIFY_PATCH` is missing or another backend is compiled in. `update_ev_c` only re-embeds `ecb.h` and keeps the patch; when importing a newer libev, re-apply it (limited to `backend == EVBACKEND_EPOLL` if other backends are enabled) or drop it together with the check. T14: `epoll_poll()` in `libev/ev_epoll.c` maps EPOLLERR/EPOLLHUP only to the events the fd wants (READ|WRITE when it wants none, so libev's lazy DEL of a mask-0 fd still happens even if the fd reports only EPOLLERR: TCP always adds IN and OUT to ERR/HUP, a UDP socket with a pending ICMP error does not); upstream maps them to both, so an fd waiting only for READ that gets HUP (after our `SHUT_WR`, the peer's FIN) costs an `EPOLL_CTL_MOD` to the mask the kernel already has (for a non-zero mask the kernel registration always equals it, and epoll reports only registered IN/OUT bits). `my_ev.cpp` fails the build if its marker `TPM_LIBEV_EPOLL_HUP_PATCH` is missing; re-apply it when importing a newer libev.

## Code Conventions & Common Patterns

- Style is pragmatic C-with-classes C++11: global process state, `struct` data holders, `using namespace std`, C socket APIs, `char*`/fixed buffers, and manual lifecycle management.
- Naming is mostly `snake_case`; types commonly end in `_t` (`address_t`, `tcp_pair_t`, `lru_collector_t`). The parsed rules are `app_config.rules` (read-only after startup); runtime forwarding state lives in each worker's `rules` (`worker_t`, M1); each `forward_rule_t` owns its listener fds and TCP/UDP managers.
- Keep networking nonblocking: create sockets with `SOCK_NONBLOCK|SOCK_CLOEXEC` passed to `socket()` / `accept4()` instead of a follow-up `fcntl` (`setnonblocking()`). Use `set_buf_size()` (on TCP sockets only when `sock_buf_explicit`), `set_udp_buf_size()` for UDP sockets, and `close()`; once a pair exists, its fds are closed only by the managers' `erase()`/`erase_closed()`, after its watchers are stopped.
- Logging: `mylog(level, ...)` checks the level before calling `log0()`, so arguments of filtered messages are not evaluated; `log0()` itself does not check `log_level`. `mylog_unfiltered(level, ...)` skips the check except at `--log-level 0`; only the SIGUSR1 stats use it (D26). `log0()` is declared with `__attribute__((format(printf,5,6)))`, so `-Wformat` checks every `mylog` call. It formats the whole line into a stack buffer and writes it with one `fwrite` (the timestamp and each level's `color[time][LEVEL]` prefix are formatted once per second into unlocked function-local statics, so only the event-loop thread may log: the DNS worker hands errors back through `dns_result_cb()`; the timestamp uses `localtime_r` because glibc's `localtime()` re-checks `/etc/localtime` on every call; `enable_log_color` is not part of the cache key, so it must not change once `log0()` has run: only the pre-scan at the top of `process_arg()` sets it, and the one earlier `log0()` call, the `ev_default_loop()` failure in `main()`, exits immediately). stdout is flushed per line only on a tty; otherwise it stays fully buffered (4 KiB with glibc, 1 KiB with musl) and is written when the buffer fills, by `clear_timer_cb()` every `timer_interval` (400 ms), and by `myexit()`, so lines written right before an abort, an unhandled signal, or SIGKILL can be lost.
- Addresses: connections keep the client address as `address_t` (`tcp_pair_t::addr`, `udp_pair_t::adress`) and format it only inside `mylog` arguments with `get_str()`, so filtered lines and the per-packet UDP path do no formatting. `get_str()` returns one static buffer: use it at most once per `mylog` call and only on the event-loop thread; otherwise `to_str()` into a local `char[max_addr_len]`. `to_str()` hand-formats IPv4, v4-mapped IPv6 (`::ffff:a.b.c.d`, how IPv4 clients of a dual-stack `[::]` listener appear) and the port (no `sprintf`); other IPv6 goes through `inet_ntop`. `to_str()` must not change `errno`: a `mylog` call may evaluate `get_str()` before `get_sock_error()`.
- Error handling uses `mylog(level, ...)`, `myexit()`, and `assert()` for invariants. Invariants checked per event, per packet or per connection (the callbacks, `tcp_accept_one()`, `select_remote_index()`, `lru_collector_t`, the managers' `erase()`, `address_t::get_len()`/`from_sockaddr()`/`to_str()`) use `DEBUG_ASSERT()` (`common.h`): `assert()` only when `ENABLE_DEBUG_ASSERT` is defined (`make all OPT=-DENABLE_DEBUG_ASSERT`, i.e. the `-assert` builds that `make test` runs, and `make fast`/`make debug`), otherwise `((void)sizeof(!(x)))`, so `make all` and `make release` compile them out. The expression must have no side effects (release builds do not evaluate it, and no compiler warns) and no lambda. Use it only for internal invariants, never to validate input: in a release build a violated check is undefined behaviour instead of an abort, either a crash without a message (e.g. `erase(end())` in the UDP manager) or silent corruption (a leaked block and lost data in `tcp_cb()`, cross-talk between pairs). `ENABLE_DEBUG_ASSERT` together with `NDEBUG` is a `#error`, because it would silently drop every assert; zig defines `NDEBUG` at `-O1` and above, so the `docker/build.sh cross` compile check builds no asserts at all. Release builds (`make all`, `make release`) deliberately do not define `NDEBUG` (X1, D28): after T12 that would only remove libev's checks (nothing measurable on any workload), and without libev's `corrupted watcher` assertion a missing `ev_io_stop()` whose pair and fd number are reused turns from an abort into a livelock (`fd_reify()` walks a looped watcher list forever: 100% CPU, SIGTERM never handled, the process does not exit). Do not add `NDEBUG` to `FLAGS` or the release targets; a release built with zig needs `-UNDEBUG`. Startup and config checks keep plain `assert()`. Fatal setup errors usually log `log_fatal` then exit; runtime network errors usually log and close/erase the affected connection. `myexit()` flushes stdout and calls `_exit()`: no static destructors or `atexit` handlers run, because the detached DNS thread may still be blocked on `dns_cv` (glibc's `pthread_cond_destroy` would wait for it forever), so do not put shutdown work in destructors.
- Async work is libev-based only: `ev_io_init/start/stop`, `ev_timer`, `ev_signal`, `ev_async`, `ev_prepare` (the UDP return-batch flush), `EV_READ`, and `EV_WRITE`. When changing watcher events on the same fd, existing code stops the watcher, changes `events` (no `ev_io_init`, T13), then restarts it.
- Avoid introducing new allocation-heavy abstractions in hot paths. TCP data goes through `tcp_scratch` and `tcp_buf_pool` blocks (or `tcp_pipe_scratch` and `tcp_pipe_pool` pipes for splice) and connection objects through `obj_pool_t`, so TCP forwarding and TCP connection setup do not call `malloc()` once the pools have grown to the peak (free blocks beyond 64 are freed and allocated again in the next backpressure burst); neither does a new UDP session once its rule's session table has grown to the peak. UDP reads packets in both directions into the worker's `udp_batch` (the return path shares its slots, D36).
- `libev/ev_wrap.h` is generated by `libev/update_ev_wrap`; do not hand-edit generated or vendored libev files unless the change is explicitly about the embedded event loop.

## Runtime/Tooling Preferences

- Required language/toolchain: C++11 with `g++`/compatible compiler and GNU Make-style `makefile`.
- No Node, Bun, Python package manager, or dependency lockfile is used for the project build. Go (tests, `bench/fwdbench`) and Python 3 (bench summaries) use only their standard libraries.
- libev is always embedded (`my_ev.cpp` includes `ev.c`) and built with the epoll backend only; `event_loop()` logs the active backend (`event backend: epoll`) at startup.
- Linux is the only supported platform (glibc distributions and OpenWRT/musl; deployed directly on hosts). Windows/macOS/FreeBSD/Cygwin targets and code paths were removed; do not add non-Linux fallbacks. On a macOS dev machine, build and test through `docker/build.sh` / `make test`.
- Keep `libev/` treated as third-party vendored code. Prefer changing project wrapper/configuration files before modifying libev internals; the only local changes that affect Linux builds are the `fd_reify()` patch (T13) and the `epoll_poll()` ERR/HUP mapping (T14).
