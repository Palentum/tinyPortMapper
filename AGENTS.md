# Repository Guidelines

## Project Overview

tinyPortMapper (`tinymapper`) is a lightweight C++11 TCP/UDP port mapping and forwarding utility. It supports single-rule CLI startup and config-file startup with multiple forwarding rules in one process, forwarding IPv4, IPv6, and 4-to-6 / 6-to-4 traffic. The data plane is event-driven and embeds `libev` directly into the binary.

## Architecture & Data Flow

- `main.cpp` owns the application flow: CLI parsing, socket setup, libev watcher registration, signal handling, TCP/UDP callbacks, and connection cleanup.
- `process_arg()` parses single-rule CLI options (`-l`, `-r`, `-t`, `-u`) or `-c/--config <path>` into `app_config.rules`; log, color, socket-buffer (`--sock-buf`, `--udp-listen-buf`), `--disable-tcp-nodelay`, `--disable-splice`, `--pipe-size`, `--udp-gro`, `--threads` and `--cpu-affinity` options remain process-wide (command line only). `--log-level`, `--disable-color` and `--enable-color` must take effect before the first log line, so a pre-scan at the top runs `getopt_long` over a copy of `argv` (GNU getopt and musl permute the vector they parse; the `argc=` echo keeps the original order) with the same `long_options` and optstring and `opterr=0`, handles only those three and leaves every error to the main pass, whose branches for them are empty: `--log-level=N`, unique-prefix abbreviations, `--` and a value taken as another option's argument are read the same way by both passes, and a level that is not a number in 0–6 (`abc`, empty, `-1`) is fatal (D93; the earlier pre-scan matched exact spellings in `argv` and ignored the other forms silently). Numeric values (`--log-level` in the pre-scan, `--sock-buf`, `--udp-listen-buf`, `--pipe-size`, `--threads` unless `auto`) go through `parse_uint_arg()`: plain decimal digits only (leading zeros allowed); a sign, whitespace, a unit suffix, hex, an empty value or one above `INT_MAX` returns -1 and gets that option's existing fatal, `invalid log_level` or the range message (D100; `sscanf("%d")` read `512k` as 512, `4,8` as 4 and wrapped `4294968320` to 1024). A getopt error (unknown or ambiguous option, missing value) prints `getopt_long`'s own reason on stderr, followed by the fatal line `invalid command line option, see -h`. Arguments left after the main pass (`optind < argc`: a stray word, anything after `--`) are fatal (`unexpected argument '<arg>'`, quoted so that an empty argument such as an unset systemd `${VAR}` shows as `''`), and so is a second `-l` (D101; before, `-r a:1 b:2` used only `a:1`, `-c a.toml b.toml` loaded only `a.toml`, and a later `-l` replaced the earlier one). `-l` and TOML `listen` (`finalize_config()`) are parsed by the same `address_t::from_str(str, err, err_len)`: an `a.b.c.d:port` or `[ipv6]:port` literal only, split like the literal branches of `parse_remote_target()` with the same static helpers and wording (`missing ':'`, `invalid port`, `invalid IPv4 address`, ...; an empty value is `empty address`, as config.cpp said before), no DNS, no logging, no exit; the caller logs `-l <value>: <reason>` or `<path>:<line>: listen: <reason>` at fatal (D102; the old `from_str()` used `sscanf("%[^:]:%u")`, so `-l 127.0.0.1:80abc`, `:80:90`, `:+80` and `:4294967376` bound port 80, its errors were `log_error` lines that `--log-level 1` hid, and config.cpp checked `listen` with its own `validate_address_literal()`). `parse_port_str()` rejects port 0 for listen and remote addresses alike (`port must be between 1 and 65535`, D103: a listen port 0 bound a different random port per socket, a remote port 0 failed every connection). `load_config_file()` checks `in.bad()` after the `getline` loop: libstdc++ turns a failing `read()` into an `ios_failure` that `getline` swallows into `badbit`, which ended the loop like EOF and started with the rules read so far; it is now `<path>:<line>: path: failed to read config file` (D104; libstdc++ only: libc++, i.e. the zig `cross` compile check, which is not shipped, ends `underflow()` on a failed `fread` as EOF without `badbit`). TOML string values (`listen`, `remote`, `balance`, `extra_remotes` items) containing a NUL byte are fatal (`NUL byte inside string`): they are parsed through `c_str()`, which silently dropped everything after the NUL (`listen` had been rejected by `validate_address_literal()` checking the whole `std::string`).
- `event_loop()` runs on the main thread. It creates `--threads` workers (`worker_count`, 1–64, default 1 per D5 until the P4 gate passes; `auto` = the CPUs in `sched_getaffinity`, at most 8), each with its own `ev_loop_new(EVBACKEND_EPOLL)` loop (fatal if the backend is not epoll), materializes every worker's `forward_rule_t` copies from `app_config` (`worker_add_rule()`), then creates the listeners rule by rule (`start_forward_rule()`): one socket per worker for each enabled protocol (M2; `SO_REUSEPORT` only when `worker_count > 1`, D67: with one worker it would only add a reuseport selection in softirq to every SYN and datagram sent to the listener, measured as −3% client send rate and +2.5% forwarder CPU per datagram for single-flow 1400-byte UDP over loopback, and the listener stays exactly as before M2), all bound (TCP: listening) before any worker thread runs, so the reuseport group is fixed for the process lifetime (a change of membership remaps the UDP 4-tuple → socket hash); each worker's accept/read watcher is started on that worker's loop with `watcher->data` pointing at its own rule copy. With `--cpu-affinity` (M5, D70, D72, D73), `cpu_affinity_init()` runs before the workers are created: it takes the first `worker_count` CPUs of the main thread's `sched_getaffinity` mask in ascending order into `worker_cpus` (scanning all `8*sizeof(cpu_set_t)` bits, since musl before 1.2.4 defines `CPU_SETSIZE` as 128; fewer → fatal; one info line `cpu affinity: workers on cpus …`) and, when `worker_count > 1`, builds `cpu_steer_code`, a cBPF program `ld [SKF_AD_OFF+SKF_AD_CPU]; jeq cpu_k → ret k …; ret 0xffffffff` (0xffffffff, not N: an out-of-range index makes the kernel fall back to its 4-tuple hash, while N would hand every connection received off the worker CPUs to a same-uid socket that joined the group later; `SKF_AD_OFF+SKF_AD_CPU` is negative and needs a `u32_t` cast inside `BPF_STMT`). After the TCP per-worker loop, `cpu_steer_attach()` sets `SO_ATTACH_REUSEPORT_CBPF` on worker 0's TCP listener, which applies to the whole group (TCP sockets join the group at `listen()`, in worker order, so group index k is worker k); a failure (needs 4.6) logs a warn the first time, then debug, and leaves the hash. UDP groups get no program (D73): the program would run for every datagram, and where a client's receiving CPU keeps changing (WireGuard ingress, fragments, veth, threaded NAPI) the client would get sessions on several workers. `worker_main()` pins its thread with `sched_setaffinity(0, …)` to `worker_cpus[id]` before `ev_run` (failure: warn, runs unpinned); the main and DNS threads are not pinned. `worker_cpus` and `cpu_steer_code` are written before `pthread_create` and stay out of `worker_t`, so the forwarding code is unchanged with the option off (release-build disassembly differs from `d67de1f` only in the startup functions). Before each group, `listen_probe()` binds a socket with `SO_REUSEADDR` but without `SO_REUSEPORT` (so TIME_WAIT does not matter) and closes it: an address already in use (another instance, an overlapping rule such as `[::]:p` and `0.0.0.0:p`, or another same-uid program that set only `SO_REUSEPORT`) still fails with the usual bind error instead of silently joining a same-uid reuseport group; for UDP, a holder that set only `SO_REUSEADDR` (including another tinymapper) can still share the port, as before M2 (review L-1). With every listener open, `check_forward_loops()` (D107) refuses a forwarding loop: an edge from rule u to rule v exists when one of u's remotes (its startup address; `0.0.0.0`/`::` count as loopback, v4-mapped as IPv4) lands on v's listener of the same protocol, i.e. equals v's specific listen address (sure) or has the port of v's wildcard listener (`0.0.0.0`, `[::ffff:0.0.0.0]`, or `[::]`, which takes IPv4 too unless `IPV6_V6ONLY`) and is loopback or a `getifaddrs()` address (sure for TCP, whose listener leaves no other socket a more specific bind except a later same-uid `SO_REUSEPORT` one; unsure for UDP, where a `SO_REUSEADDR` socket on the exact address, e.g. systemd-resolved's 127.0.0.53:53, receives the datagrams). A sure edge with a sure path back (self-edge or cross-rule cycle) is fatal, an unsure edge on any cycle logs a warn, chains A→B→outside pass; later DNS changes are not checked. Then it builds the DNS master table, starts the main thread's 400 ms timer, the stats `ev_async`, and on every worker loop its 400 ms timer, control `ev_async` and (if a rule enables UDP) the prepare watcher; blocks all signals except SIGABRT and the synchronous fault signals (SEGV, BUS, FPE, ILL, TRAP: musl before 1.1.20 does not unblock SIGABRT in `abort()`, review L-3), starts the DNS threads if a remote is a hostname (min(distinct hostnames, `dns_thread_max` = 4), D108; a `std::system_error` from `std::thread` is logged as fatal and exits like a failed worker `pthread_create`, D106), creates the worker threads (`pthread_create` with 256 KiB stacks, since musl 1.1.16 defaults to 80 KiB; named `worker<N>` with `PR_SET_NAME`), restores the mask and runs the default loop.
- Workers (M1, D59/D60; threads M2–M6, D61–D64): all per-worker mutable state lives in `worker_t`: its loop and time cache (`loop_clock_t clock`), the rule runtimes (`list<forward_rule_t> rules`: listen fds and watchers, the TCP/UDP managers with their LRUs, session tables and counters, the remote address copies), the object pools (`tcp_pair_pool`, `udp_pair_pool`), `tcp_buf_pool` and `tcp_scratch`, `tcp_pipe_pool` and `tcp_pipe_scratch`, `udp_batch`, the `udp_flush_watcher`, its 400 ms `tick_timer` and the control channel (`ctrl_watcher` `ev_async`, `ctrl_mutex`, `ctrl_queue`; the new locks are `pthread_mutex_t`, not `std::mutex`, review I-5. With `_GLIBCXX_GTHREAD_USE_WEAK` 1, libstdc++ reaches pthread only through weak symbols, and a static link does not pull in what nothing references strongly. The OpenWRT SDK GCC 5.4 and Alpine both define it 0 for musl, so `std::mutex` is a real lock there (D97). Against glibc < 2.34 it is 1, and a static link on Debian/Ubuntu (RHEL 8 merges `libpthread.a` and was not affected) leaves the weak `pthread_cond_*` and `pthread_detach` behind the DNS thread's `std::condition_variable` and `std::thread::detach()` at 0 (crash at startup with a hostname remote), and NSS's second `libc.so.6` is uninitialized in non-main threads, so `getaddrinfo` there crashes (arm64) or misses `/etc/hosts` (x86-64). `make all` therefore links dynamically against it (D95), and the DNS thread keeps its `std::thread`/`std::mutex`/`std::condition_variable` (D96)). Hot paths reach it through `forward_rule_t::worker` (pairs and sessions through `owner`, listener watchers through `data`, the prepare, timer and control watchers' `data` is the worker); the managers keep `worker` for `erase()` and their `lru_collector_t` keeps `clock`. No `thread_local` on hot paths (on mips24kc the TLS pointer is `rdhwr`, possibly emulated by the kernel) and no `ev_userdata()` (an out-of-line function in `ev.c`). `worker_new()` constructs the worker with placement new on anonymous `mmap` pages that are never freed, marked `MADV_NOHUGEPAGE` (with THP=always a huge page would make 2 MiB resident at once, at startup on kernels that 2 MiB-align large anonymous mappings, and khugepaged collapses such ranges too, which affected the BSS before; review L1): zero-filled and populated on demand, so `udp_batch`'s overflow areas stay non-resident until large datagrams land and the bytes no constructor writes (64-bit musl `msghdr` pads) stay 0; `new` does not guarantee zeroed memory and a `memset` would make all of it resident. Threads (D62): there is always a main thread plus `worker_count` worker threads, also for `--threads 1`; each worker runs `ev_run()` on its own loop in `worker_main()` and touches only its own state. The main thread runs the default loop: signals, `main_timer_cb()` every 400 ms (DNS scheduling, then `fflush`), the DNS result `ev_async` and the stats `ev_async`; it has its own `main_clock` (it must not read a worker loop's `mn_now`). It reaches workers only through `worker_post()` (a `worker_msg_t` appended to the worker's queue under `ctrl_mutex`, then `ev_async_send`), handled by `worker_ctrl_cb()` on the worker's loop between other callbacks: `worker_msg_dns` (S5), `worker_msg_stats` (D63), `worker_msg_exit` (M6). Each worker's `clear_timer_cb()` runs `worker_tick()` (LRU clearing, restarting stopped listener watchers, pipe-pool flag resets and regrow) on its own loop. DNS (M3, S5): the main thread owns the master table `dns_targets` (per domain remote: host, port, current address, last refresh time, query pending), schedules refreshes from it with `main_clock` (all entries of one hostname go out as one `dns_refresh_request_t`, host plus `{rule, remote, port, current address}` entries, and stay in step, so each hostname has at most one lookup in flight; `dns_worker_main()` resolves it once and splits the result per entry by port and current address, `resolve_domain_addresses()` taking `find_count` current addresses; `getaddrinfo` has no deadline, glibc's TCP fallback `send_vc` blocks in `connect`/`read` with no timeout and a server that accepts and never answers holds it forever, and with one FIFO DNS thread and one lookup per rule a stuck lookup stopped every hostname's refresh for good and N rules on one slow name were N serial lookups per cycle, review Low, D108; four hostnames stuck at once still stall the rest; a lookup pending for 2 refresh intervals, running or queued behind busy threads, logs one warn per hostname, `no lookup result for N s`, and one info when it returns, D109), applies results there (a failed resolve logs one warn; the current address counts as unchanged when it appears anywhere in the full `getaddrinfo` result and is still routable from this host, although `resolve_domain_addresses()` stores only the first `dns_max_result` = 16, review Medium #8, D92; it skips unspecified addresses, `0.0.0.0`, `::` and `::ffff:0.0.0.0`, the blocked-name answer of AdGuard Home's `default` and Pi-hole's NULL mode and of `0.0.0.0` hosts blocklists: as a destination Linux turns them into loopback, so a client reached a loopback-only service on the remote port, and with remote port = listen port the forwarder connected back to its own wildcard listener until fds ran out (one packet: 1016 UDP sessions at nofile 1024, every rule stalled). An answer with nothing else fails like NXDOMAIN: fatal at startup, a warn and the current address kept on refresh; literal `-r 0.0.0.0:P` is unchanged, D98; `pick_remote_addr()` picks the address at startup (`parse_remote_target()`, one info line when it is not `addrs[0]`) and on refresh (`dns_worker_main()`): the current one while it is in the result and routable, else the first routable one, else the current one or `addrs[0]`. `addr_routable()` `connect`s a UDP socket of the address's own family, which only looks up the route, as glibc and musl ≥ 1.1.20 do when sorting; fd, memory or ephemeral-port shortage counts as routable. The release builds' musl 1.1.16 probes IPv4 through v4-mapped addresses on an AF_INET6 socket, so where AF_INET6 sockets cannot be created (`ipv6.disable=1`, no `CONFIG_IPV6`), or with `bindv6only=1` and no IPv6 route, no candidate is usable and IPv6 sorts first (precedence 40 > 35): every connection to a dual-stack name failed and refreshes kept the address. On any libc an address whose route disappeared later was kept while DNS still returned it (review Medium #10, D99) and, when the address changed, posts `{rule, remote_index, new_addr}` to every worker; `worker_dns_update()` replaces that worker's copy and bumps the remote's `gen` (every pair and session records `gen` when it is created, so a different value means it was created for an older address); new connections use the new address at once, and the old pairs and sessions stay as long as they work (review Medium #9, D94: one absence in a DNS answer is not proof the address is gone, subset-answer domains (weighted/GSLB/CDN) and one-family partial results from glibc and musl 1.1.16 used to drop every connection every 30 s–7 min). `remote_sweep()` closes only the unresponsive ones of that worker: TCP when the upstream socket's `TCP_INFO` shows `tcpi_retransmits` or `tcpi_probes` ≥ 3 (consecutive unanswered RTOs/SYNs, or zero-window/no-route probes) or the getsockopt fails, UDP when `unans` (time of the first upstream datagram after the last reply, set in the upstream group loop from the value `lru.update()` returns, cleared on a reply) is ≥ 10 s old. It runs once in `worker_dns_update()`, which logs `changed from … closed unresponsive tcp=… udp=…, kept tcp=… udp=…` (one line per worker, with its own counts), and again from `worker_tick()` every 30 s while old pairs remain (`sweep_at`), logging `old address check: …` only when it closes something. A TCP pair whose last check saw nothing in flight (`sweep_idle`: unacked, backoff, retransmits, probes all 0) and that has had no traffic since (`ts + lru_move_interval <= swept_at`) is skipped, because the kernel has nothing to retransmit; without that, subset-answer domains always have old pairs and every 30 s cost one getsockopt each (2–5 µs, 40–107 ms per 20k pairs). `max_conn_num` (M4, S7) is per rule across all workers: `rule_shared[]` (`rule_shared_t`, allocated by the main thread, never freed) holds a `std::atomic<int>` for TCP and UDP per rule (and the per-direction GSO log-once flags), the managers keep a pointer (`conns`); `tcp_accept_one()`/`udp_new_session()` take a slot with `fetch_add` and give it back on every failure path, `erase()`/`erase_closed()` give it back (relaxed); the counts in log lines stay the worker's `lru.size()`. Roundrobin (D85) is one selection sequence per rule shared by all workers, not one smooth-WRR state per worker (every worker starting at `current_weight=0` sent a few long-lived flows spread over N workers mostly to the heaviest remote, e.g. 2 WireGuard peers with `--threads 4` both to remote 0 in 75% of starts): `rr_build_seq()` runs the nginx smooth weighted round robin from the zero state for one period (the sum of the weights T ≤ 255×255 steps, after which every node is back at 0; asserted) into `rule_shared_t::rr_seq` (one byte per pick) before the workers start, and `select_remote_index()` takes `rr_seq[rr_next.fetch_add(1, relaxed) % T]` through `forward_rule_t::shared`, so the k-th TCP connection or UDP session of a rule gets the same remote as with one worker (the 32-bit index wraps after 2^32 picks, one out-of-phase pick when T does not divide 2^32); iphash keeps no state. Exit (M6, S8): SIGTERM/SIGINT log on the main thread, `workers_stop()` posts `worker_msg_exit` to every worker, each breaks its loop, flushes a pending return batch and posts `workers_exited`; the main thread waits at most 1 s in total (`sem_timedwait`, not `pthread_timedjoin_np`, which musl 1.1.16 lacks), logs a warn for workers that did not stop, then `myexit(0)`; a fatal error in a worker still calls `myexit()` directly. Signals: worker threads and the DNS threads are created with all signals blocked except SIGABRT and the synchronous fault signals, so process signals reach libev's handler on the main thread (the default loop uses `sigaction` handlers, not signalfd); `main()` starts the SIGPIPE and SIGUSR1 watchers before `process_arg()` but SIGTERM and SIGINT only after it (D105): while arguments are parsed and hostname remotes are resolved synchronously (the resolvers retry `poll()` after EINTR) these two keep the default disposition and end the process at once, and from there on they are deferred to `ev_run` for the orderly exit; the three signal log lines end in `\n` (before, the M6 timeout warn was glued onto the exit line); a SIGPIPE raised by a worker's `send`/`splice` to a reset peer stays pending on that thread and is not logged (the `got sigpipe` line appeared before M2). Process-wide state: options and startup-computed values are read-only after `event_loop()` starts the threads (`tcp_pipe_size`, `splice_turn_max`, `tcp_pipe_min_size`, `tcp_pipe_max_free`, `udp_gro`, `worker_count`); learned flags are relaxed `std::atomic<int>` (`disable_splice` set at run time when splice is unavailable, `udp_gso_hdr_cap`, the write-branch EAGAIN log-once, `common.cpp`'s `udp_buf_force`, whose fallback debug line is written only by the thread that clears it); `udp_gro_listen()`'s `gro_socks` and `udp_gro` change only at startup on the main thread. Per-worker memory (S12): each worker has its own pools, scratch block and pipe, `udp_batch` (~4.2 MiB virtual), listeners (listen backlog and UDP listen buffers per socket) and a 256 KiB stack; the idle pipe pool is capped at 1024 pages for the whole process, split evenly across workers with at least one per worker (D64, `tcp_pipe_max_free`), while the 64 free blocks of D19 are per worker.
- TCP flow: `tcp_accept_cb()` accepts the pending local clients of one worker's `forward_rule_t` (its own listener; with N > 1 workers the listeners form a `SO_REUSEPORT` group and the kernel spreads new connections over them by 4-tuple hash), calling `tcp_accept_one()` until `accept4(SOCK_NONBLOCK|SOCK_CLOEXEC)` returns EAGAIN (silently) or `max_accept_per_round` (8) clients were taken in this loop iteration (the listener must stay nonblocking, since the last `accept4()` of a round normally returns EAGAIN); any other accept failure and an immediate upstream `connect()` failure (EADDRNOTAVAIL first scans the whole ephemeral port range) also end the round, while `max_conn_num` (counted per rule across all workers, M4), a failed connection-object allocation and an upstream `socket()` failure only drop that client and move on (if `accept4()` fails with anything but EAGAIN/EINTR/ECONNABORTED, e.g. EMFILE/ENFILE/ENOMEM or an LSM denial, the client stays in the backlog, so the rule's accept watcher is stopped and `clear_timer_cb()` restarts it on its next tick; an `EV_ERROR` on the accept watcher, e.g. a failed epoll re-add, is logged and retried the same way), takes a `tcp_pair_t` from `tcp_pair_pool` (if a new slab cannot be allocated, only that client is closed with a warn, before anything is sent to the upstream or the roundrobin index advances), opens a nonblocking remote socket to that rule's `remote_addr` (if `socket()` fails, e.g. EMFILE, only that client is closed and the pair goes back to the pool) and starts a nonblocking `connect()` (an immediate failure other than EINPROGRESS, e.g. ENETUNREACH or EADDRNOTAVAIL, closes the client with a warn), fills the `tcp_pair_t` with both fds and points both watchers' `data` at it, then `tcp_cb()` relays data between the two endpoints while toggling `EV_READ` / `EV_WRITE` watchers for backpressure. A callback that reports both events runs the read branch and then the write branch (D86): with the read branch alone, data held for a socket that stays readable was sent only when that socket happened not to be readable or a send toward its peer came up short. Every `recv()` reads up to `max_data_len_tcp` (64 KiB) into the worker's `tcp_scratch` block; if `send()` takes all of it the block stays scratch for the next `recv()`, otherwise (partial or failed send, or upstream still connecting; a send error is left to the write branch, which closes the pair) the block itself is handed to that direction (`tcp_info_t::buf`, with `begin`/`data_len`; no copy), reading from the source stops, and the next `recv()` first takes another block from `tcp_buf_pool`. A direction holds a block only while it has unsent data (`buf` is non-null exactly when `data_len` is non-zero): the write branch returns it once drained, and the managers return held blocks when they release a pair. The pool keeps at most `tcp_buf_pool_max_free` (64) free blocks and `free()`s the rest; an empty pool `malloc()`s a new block. If that `malloc()` fails (only under `RLIMIT_DATA`/`RLIMIT_AS` or `vm.overcommit_memory=2`; with default overcommit, exhaustion means the OOM killer), the pair whose `recv()` needed the block is closed with a warn: whichever pair reads next, not necessarily the one holding memory, and the read branch runs first even when that side could have drained its own held block by writing. Other allocation failures still abort the process: libev growing its fd array for a new fd peak (`ev_realloc`), the DNS threads' queues. User-space memory therefore follows backpressure: an idle pair is about 0.3 KB, but each direction whose destination is slower than its source holds a whole 64 KiB block until it drains (at most 2 × 64 KiB per pair, with no global cap besides `max_conn_num`). Bulk directions bypass user space with splice (B1/B2, D46–D48): each direction remembers whether its last successful read (recv or splice) returned at least `splice_read_min` (16 KiB) (`tcp_info_t::splice_next`, recomputed after every read, not sticky, so small-message traffic never splices: a 64-byte splice costs about 4% more than recv+send, a 16 KiB one 19% less). If it did, the other side is connected and `--disable-splice` was not given, the read is `splice(src → tcp_pipe_scratch, tcp_pipe_size, SPLICE_F_MOVE|SPLICE_F_NONBLOCK)` and the data leaves through `splice(pipe → dst)` after `nodelay_before_send()` (no `SPLICE_F_MORE`: the kernel adds `MSG_MORE` itself between the pipe buffers of one call). `tcp_pipe_size` (B3: `--pipe-size` in KiB, 64–1024, default 256 KiB, D55/D57) is both the size new pipes are grown to and the most one splice reads, so it bounds what a waiting direction holds in a pipe; pipe contents are kernel pages charged to neither `tcp_mem` nor the memcg (D51 had 64 KiB). Since 5.5 (backported to 4.19.y and 5.4.y) the kernel caps a splice into a pipe at its free slots × PAGE_SIZE; 4.9.y/4.14.y do not, so there a 16-slot pipe can take sixteen 32 KiB local fragments. Every skb fragment takes one slot: local senders (loopback, veth) produce 32 KiB fragments, a NIC after GRO about one MSS each, so a 16-slot (64 KiB) pipe moves about 22 KiB per splice from a NIC and a 64-slot (256 KiB) one about 90 KB (B12 review M3; the Docker bench cannot show this). While each splice-in returns at least `splice_more_min` (64 KiB) and the splice-out writes all of it, the callback reads again, requesting `min(tcp_pipe_size, splice_turn_max - moved)`, until it has moved `splice_turn_max` bytes (D53/D55/D56): 256 KiB, or (size / 256 KiB) × size above 256 KiB (1 MiB at 512, 4 MiB at 1024); `--pipe-size 64` is exactly the B2 behavior (4 × 64 KiB). Measured with 8 loopback streams on one forwarder CPU plus a same-process 64-byte round trip: 64 KiB × 4 reads 115 Gbit/s and p50 295 µs, 256 KiB × 1 161 Gbit/s and 216 µs (part of that gain is a loopback artifact: a 65536-byte splice-out is one 65483-byte MSS segment plus a 53-byte tail), 256 KiB × 4 173 Gbit/s but 774 µs; 1 MiB × 4 207–213 Gbit/s with p99 2.8 ms, like realm `-p 256` (experiment variants; the B3 formal batch with the real build: default 159.8 Gbit/s, p50/p99 220/328 µs; `--pipe-size 1024` 204.3 Gbit/s, p50/p90/p99 201/2,579/2,923 µs; realm `-p 256` 214.1, 139/958/2,624). In later reads an EOF or EAGAIN ends the loop and the next callback handles it as its first round (EOF stays readable), but any other error closes the pair at once: splice has already consumed `sk_err`, so the next read would return 0 and an RST would be forwarded as a clean EOF. The pipe is handled like the scratch block (D47): written out completely, it stays the scratch pipe; otherwise (partial write, EAGAIN, or an error left to the write branch) the pipe with its data goes to the direction (`tcp_info_t::pipe`; `data_len` counts the unsent bytes in either the block or the pipe, never both, and `data_len != 0` exactly when one of them is held), reading the source stops, and the write branch drains it with splice and returns it to `tcp_pipe_pool` (free pipes kept up to `tcp_pipe_pool_t::max_free`, the rest closed: 1024 pages in total for the whole process, split evenly across the workers with at least one pipe each (D64: 64 × 16 / slots per pipe / `worker_count`, so with one worker 64 at 64 KiB, 16 at 256 KiB, 4 at 1 MiB; 8 at 256 KiB per worker with 2 workers), because the uid's pipe quota counts idle pipes too and a count cap of 64 would let `--pipe-size 1024` keep the whole default soft limit, review M1; `free_pipes[]` stays sized `tcp_pipe_pool_max_free` (64); while `quota_hit` is set, i.e. after `create()` got a pipe of fewer than 16 slots and until `clear_timer_cb()`'s next tick, which then trims the free list back to `max_free`, `put()` keeps up to 64, because during that `blocked` window drained pipes are reused at once and closing them sent directions to recv (re-review R1: non-root 2000 stalled connections at `--pipe-size 1024` 63.4 → 73.2 Gbit/s, default unchanged; fd shortage does not set it and `tcp_pipe_trim()` clears it, D52; free pipes can then hold 130 fds, as before review M1). After every partial splice-out (the hand-off above and a partial write in the write branch) `tcp_unshrink_sndbuf()` checks the destination (D54): when the host is under `tcp_mem` pressure the kernel shrinks an unlocked sndbuf to half its queue (`sk_stream_moderate_sndbuf`) and does not grow it back while the pressure lasts; with a loopback-class MSS (65483) that leaves one segment in flight and the receiver delays its ACK (~40 ms), which halved splice throughput with 2000 stalled loopback connections (the copy path rarely gets shrunk; why the zero-copy chain does is not known). So if `SO_SNDBUF` < 2 × `TCP_MAXSEG` it sets `SO_SNDBUF` to 2 × MSS (the kernel doubles it to four segments, 256 KiB on loopback, and locks it, so that socket no longer autotunes); the MSS is read once per direction into `tcp_info_t::mss` (0 unread, -1 on failure) and while 2 × MSS ≤ `tcp_min_sndbuf` (4608, `SOCK_MIN_SNDBUF`), e.g. any MSS 1448 path, the function returns at once from then on (the smallest sndbuf already holds three such segments; gating on the sndbuf alone would lock new WAN connections, whose sndbuf starts near 87 KB); otherwise it costs one `SO_SNDBUF` `getsockopt()` per partial write, and nothing with `--sock-buf`. A `net.core.wmem_max` below ~17 KiB would clamp the lock below the shrunk size (recorded, not handled); with `net.ipv4.tcp_wmem[2]` below two loopback segments the lock also applies without memory pressure and exceeds that cap. A held pipe always contains data, so releasing a pair closes it (`tcp_pipe_pool_t::discard()`): a pipe with data is never reused, which would send one connection's bytes to another. An empty pool creates a pipe out of line (`tcp_pipe_pool_t::create()`): `pipe2(O_NONBLOCK|O_CLOEXEC)`; a pipe whose higher fd is at or above three quarters of the `RLIMIT_NOFILE` soft limit (read with `getrlimit()` at each creation) is closed (D52: the last quarter of the descriptors is for sockets, since a backpressured direction holds a pipe and a pair can then use 6 fds instead of 2); then `F_GETPIPE_SZ`, and a pipe with fewer than 16 slots (`tcp_pipe_min_size`, 16 pages, D58; counting bytes would let a 2-page 128 KiB pipe through on 64K-page kernels) is closed (a user without `CAP_SYS_RESOURCE`/`CAP_SYS_ADMIN` in the initial user namespace whose pipes together reach `fs.pipe-user-pages-soft` gets 2 pages; container root with Docker's default capabilities is such a user, and uid 0 is shared by every root process of the host; the count is by capacity, so free pooled pipes count too: 1024 pipes of 64 KiB, 256 of 256 KiB, 64 of 1 MiB). A pipe smaller than `tcp_pipe_size` is then grown with `F_SETPIPE_SZ` (never shrunk: on 64K-page kernels the default 16 slots are already 1 MiB). If growing fails (EPERM from that quota, ENOMEM), the pipe keeps its size and is used anyway (D58): `tcp_pipe_pool.resize_fail` counts it, `grow_blocked` skips further attempts (still counted) until `clear_timer_cb()`'s next tick, and the first failure of the process logs info (`pipe_grow_logged`, shared by the workers), later ones debug. A pipe that could not be grown would otherwise stay the scratch pipe and cycle through the pool for good (review M2), so once `resize_fail` is non-zero `clear_timer_cb()` calls `tcp_pipe_pool_t::regrow()` on the scratch pipe every tick (`F_GETPIPE_SZ`, and `F_SETPIPE_SZ` if smaller; a failure sets `grow_blocked`, not counted, not logged); small pooled pipes get regrown when they become the scratch pipe. Before the event loop, unless `--disable-splice` was given, `tcp_pipe_probe()` sets `tcp_pipe_min_size` from the page size, rounds `tcp_pipe_size` up to a power of two pages as the kernel will (300 → 512 KiB; done in user space so that reads and `splice_turn_max` match the pipes even if the probe cannot set the size, review L2), creates one pipe and tries `F_SETPIPE_SZ(tcp_pipe_size)`: success takes the returned size, and EPERM with a request above `/proc/sys/fs/pipe-max-size` (no `CAP_SYS_RESOURCE`) uses pipe-max-size with a warn if `--pipe-size` was given (`pipe_size_explicit`) and an info line for the default (as D40); other failures (quota already full) are left to `create()`, and an unreadable `/proc/sys` with a lowered pipe-max-size is not handled (every new pipe then fails to grow, review L3). It then sets `splice_turn_max` and `tcp_pipe_max_free`, which every worker's pipe pool takes as `max_free` when it is constructed (the probe runs before `worker_new()`). Any failure (also EMFILE/ENFILE) makes that read use recv, adds 1 to the rule's `splice_fallback`, logs the reason (info the first time in the process (`pipe_fail_logged`, shared by the workers), debug afterwards) and sets `tcp_pipe_pool.blocked`, so no creation is tried until `clear_timer_cb()` clears it on its next tick. When `accept4()` or the upstream `socket()` fails with EMFILE/ENFILE, `tcp_accept_one()` calls `tcp_pipe_trim()`, which closes every free pooled pipe and the scratch pipe and sets `blocked` (held pipes contain data and stay). A splice read that fails with ENOSYS, EPERM, EINVAL or EOPNOTSUPP (splice itself unavailable, e.g. a seccomp allow-list without it; nothing was read) logs one warn, sets `disable_splice` for the rest of the process and reads with recv instead. A splice read that returns EAGAIN is retried once with `recv()`: with TCP urgent data (`MSG_OOB`) at the head of the receive queue a nonblocking `tcp_splice_read()` returns EAGAIN while `tcp_poll()` keeps reporting readable (the urgent byte does not count), so without the retry the pair would spin; `recv()` skips the urgent byte (no `SO_OOBINLINE`) as the copy path always did. A splice read of 0 is EOF and other errors close the pair, exactly like recv; a splice write to a reset peer raises SIGPIPE like `send(…, 0)` (libev's `sigpipe_cb` logs it). While the upstream is CONNECTING only recv is used. Assert builds check with `FIONREAD` (`tcp_pipe_len()`) that the scratch pipe is empty before a splice read and that a pipe is empty when it goes back to the pool. Pooled pipes keep up to `2 × (max_free + 1)` fds open per worker (34 with one worker by default, 130 with `--pipe-size 64` or while `quota_hit` is set) after the connections that used them are gone; `tcp_pipe_trim()` closes only the calling worker's free and scratch pipes (`RLIMIT_NOFILE` is per process, each worker trims when it hits EMFILE itself). Both sides run with `TCP_NODELAY` unless `--disable-tcp-nodelay` is given: the TCP listener sets it once and accepted sockets inherit it; the upstream socket gets it from `nodelay_before_send()` right before its second `send()` (T15, `tcp_info_t::nodelay_wait`), or before the first one if that is larger than `nodelay_first_max` (536 bytes, `TCP_MSS_DEFAULT`). Linux's Nagle (Minshall variant) holds a sub-MSS segment only while an earlier small segment is unacknowledged, and a first write of at most 536 bytes is never cut into a small segment at a window edge that is not MSS-aligned (a larger one can be, e.g. a backend with an 8 KiB receive buffer advertises 7240 bytes while the path MSS is 1388, and its tail then waits for that segment's ACK; measured as rare, see `docs/tasks/p1.md` T15), so a connection that writes the upstream once (CRR, a small RPC request) saves the `setsockopt`. Every `send()` in `tcp_cb()` must go through `nodelay_before_send()` first (the client side's `nodelay_wait` is always 0). The TCP listener calls `listen()` with `listen_backlog` (65535), which the kernel caps at `net.core.somaxconn` (4096 by default since Linux 5.4, 128 before); the libc `SOMAXCONN` macro is not used because musl (and glibc before 2.31) define it as 128. TCP socket buffers are left to kernel autotuning: `SO_SNDBUF`/`SO_RCVBUF` are set only when `--sock-buf` is given (`sock_buf_explicit`), then once on the TCP listener before `listen()` (accepted sockets inherit the size and the `SOCK_*BUF_LOCK` bits, so setting it on the listener unconditionally would disable autotuning for every client) and on the upstream socket before `connect()`. Connect state: while the upstream is CONNECTING (`tcp_info_t::connected==0`) its watcher waits for `EV_READ|EV_WRITE` and nothing is sent or shut down on it; a writable-only report means connected, a readable report is checked with `getsockopt(SO_ERROR)`, and an error (refused, unreachable, or the kernel's SYN timeout ETIMEDOUT; there is no separate connect timer, only the TCP idle timeout) closes the pair with a warn. Client data read meanwhile (one 64 KiB block) is held and sent once the upstream connects, before anything is read from the upstream. Half-close: an EOF from one side (`tcp_info_t::eof`) is forwarded as `shutdown(SHUT_WR)` on the other side while the opposite direction keeps flowing; if the upstream is still connecting the shutdown waits until it connects, because `shutdown()` on a SYN_SENT socket aborts the connect. The pair is released once both sides have sent EOF, or on any recv/send/shutdown error (except EAGAIN from the write branch's send or splice, D50: EPOLLOUT only reflects the socket's own free space, and when the host is above `tcp_mem[2]` or a memcg charge fails, a socket with a nearly empty queue still gets EAGAIN, so the write branch keeps `EV_WRITE` and retries on the next loop iteration; with an unlocked sndbuf the kernel shrinks it first, so only such near-empty queues, or `--sock-buf` sockets, can spin until memory recovers), or when one of its watchers gets `EV_ERROR` (libev's `fd_kill` after `epoll_ctl` fails with anything but ENOENT/EEXIST/EPERM, in practice an `EPOLL_CTL_ADD` beyond `fs.epoll.max_user_watches` (ENOSPC) or ENOMEM, for a new fd or for an established pair's fd that libev deleted from epoll while backpressure had dropped its event mask to 0 and now re-adds; libev has already stopped that watcher): a warn, and only that pair is released.
- UDP flow: `udp_accept_cb()` reads one worker's listen socket of a rule (the kernel hashes each client 4-tuple to one socket of the reuseport group, so a client's sessions and packets stay on one worker while the group is fixed) with `recvmmsg()` into its worker's `udp_batch` (U1, D34; one per worker since M1): up to `udp_batch_max` (64) datagrams per call, each into two iovecs, a 2 KiB slot (the 64 slots are contiguous) and that message's own overflow area, `max_data_len_udp` (65536) bytes in all, so MTU-sized packets touch only the slots and the ~4 MiB of overflow area becomes resident only where datagrams larger than 2 KiB land; `MSG_TRUNC` (a datagram larger than 65536) drops the packet with the `huge packet` warn. It makes one `recvmmsg()` call per callback (D35): level-triggered epoll reports the fd again in the next iteration for whatever is left, so the inbound path takes at most 64 packets of a loop iteration and other watchers (TCP, the return path) wait for at most one batch; an EAGAIN (the packet that woke the loop failed its checksum and was dropped) is not logged, other errors are logged at debug. `udp_forward_batch()` restores `msg_namelen` of every received entry (the kernel overwrites it with the address length) and looks every packet's client address up with `conn_manager_udp_t::find()`: first `last_hit` (the session the previous lookup returned; `erase()` clears it, because a released pair keeps its old address and the LIFO pool hands it to the next session, so every release of a UDP session must go through `conn_manager_udp_t::erase()`), then `sessions`, a `udp_table_t` (U2): open addressing with linear probing, a power-of-two capacity that starts at 64 slots, doubles when an insert would exceed 3/4 and never shrinks (at most 32768 slots for `max_conn_num`), slots holding the session pointer and the key's 32-bit hash (probes compare the hash before touching another session; growth re-places entries by the stored hash), backward-shift deletion without tombstones. The key is family, port and address, plus `sin6_scope_id` for IPv6 (`udp_key_eq()`; `sin6_flowinfo` is always 0 from the kernel, so this equals comparing the whole `address_t`), hashed with `fmix64` once per 64-bit word (`udp_key_hash()`, unseeded). The first packet from a new address creates the session in `udp_new_session()`, which makes room in the table first (if that `malloc()` fails, only the packet is dropped, with the same info line as a slab failure, before the roundrobin index advances), creates one connected UDP socket to that rule's `remote_addr` and takes a `udp_pair_t` from `udp_pair_pool` (if a new slab cannot be allocated, the socket is closed and the packet dropped with an info line), stores it in the rule's `conn_manager_udp`. If the socket cannot be connected because the ephemeral ports are used up (an unbound UDP socket autobinds in `connect()`, which then returns EAGAIN, not TCP's EADDRNOTAVAIL, after scanning the whole port table: about 1 ms with all 28232 default ports taken) or cannot be created because the fds are (EMFILE/ENFILE, still after `tcp_pipe_trim()`), the packet is dropped with a warn line and `worker_t::udp_new_blocked` makes that worker drop the packets of every address without a session, without trying and without logging, until its next tick clears it after `clear_inactive()` (D80); any other failure drops only that packet with an info line. Then the batch is grouped by session (U3): `udp_pair_t::batch_group` is the session's group index while a batch is being forwarded and -1 otherwise (`conn_manager_udp_t::erase()` asserts it; nothing in `udp_forward_batch()` releases a session), a counting sort lays out each session's packets contiguously in `udp_batch.out` in arrival order, and the groups go out in the order of their session's first packet, after one `lru.update()` per group, each with one `sendmmsg` on the session's connected socket (`msg_name` stays 0: an address on a connected UDP socket would redirect the datagram there). `udp_send_group()` calls `syscall(SYS_sendmmsg, ...)` directly: on 64-bit musl `sendmmsg()` is a loop of `sendmsg()` calls, because musl's `msghdr` has `int` fields plus `__pad1`/`__pad2` where the kernel has `size_t`; the raw syscall is correct only while those pads are 0, which holds because `udp_batch` lies in the zero-filled `mmap` pages of `worker_new()` (zero-initialized BSS before M1) and nothing writes them (musl's `recvmmsg()` is the real syscall and zeroes them itself). A partial `sendmmsg()` continues from where it stopped (the kernel does not report the error of the message that stopped it, so the retry finds out whether it still fails); EAGAIN drops the rest of that session's group, any other error (EMSGSIZE) only the message at that point. An ICMP error (ECONNREFUSED) caused by an earlier packet makes the send at the break point fail and is consumed by it, so the retry succeeds: only an error hit by the first packet of a group drops a packet and logs (the earlier per-packet `send()` dropped one every time); each failed call adds the dropped packets to `drop[0]` and logs one warn with their count. The return path (U4, D36) batches across sessions: `udp_cb()` (a session socket is readable) makes one `recvmmsg()` per callback into the free part of the return batch, which shares `udp_batch`'s slots and overflow areas (entries `rin`/`raddr`/`rrule`, occupying `slot[0..rn)`), at most `udp_return_quota` (16, D37) and never more than what is left of the 64 entries, so a session takes at most 16 replies per loop iteration and leaves the rest to level-triggered epoll (the inbound path takes up to 64 per listen socket per iteration, but one listen socket carries every client while each session has its own socket: with a per-session quota of 64, a forwarder slower than its senders spent each iteration on backlogged sessions and the inbound path got about 1/6 of the packets, measured with the forwarder on a third of a CPU: inbound 134 kpps before U4, 82 with 64, 130 with 16, and same-process TCP round trips p50 315 µs, 586, 335; the price of 16 is about −11% on many-session reverse floods at full CPU, `docs/tasks/p2.md`); each packet's client address is copied into `raddr` (defensive: with libev's callback order no release path can run between a session's `udp_cb()` and the next flush, since timers, the DNS async and signals are invoked before the iteration's I/O callbacks and an `EV_ERROR` only hits a session never registered with epoll; the copy keeps a future release path from redirecting a pending reply to whichever client gets the pooled object next), its rule into `rrule` (`MSG_TRUNC` drops it with the `huge packet` warn), and the session's LRU entry is refreshed once per callback. `udp_flush_return()` sends the batch grouped by rule (in order of each rule's first packet, arrival order inside), one `sendmmsg()` per rule on that rule's listen socket through `udp_send_group(..., 1)` (`rout`, whose musl pads must stay 0 like `out`), with the same partial-send/EAGAIN/one-drop semantics as inbound and the warn `[udp]sendmmsg to clients returned ...` (the listen socket is not connected, so no ICMP errors show up there; failures are e.g. EMSGSIZE for a 65527-byte IPv6 reply to an IPv4 client, or EAGAIN when its send buffer is full: 2×`listen_fd_buf_size`, 4 MiB by default with `CAP_NET_ADMIN`, otherwise 2×min(`listen_fd_buf_size`, `wmem_max`), 416 KiB before Linux 6.18; never on loopback, whose xmit orphans the skb, so tests inject it with seccomp). It runs when the batch is full, at the start of `udp_accept_cb()` before the inbound `recvmmsg()` reuses the slots (anything else that writes the slots must flush first), and from an `ev_prepare` watcher (`udp_flush_cb()`, started only if some rule enables UDP) right before libev blocks in `epoll_wait`, so a reply never waits past the loop iteration it arrived in. Not `ev_check`: libev invokes the pending watchers of one priority in reverse order of queueing (`ev_invoke_pending`), and check watchers are queued last, so a default-priority check watcher runs before the iteration's I/O callbacks. A receive error other than EAGAIN (e.g. ECONNREFUSED from an ICMP port unreachable) is logged as `[udp]recv failed`; EAGAIN is silent. An `EV_ERROR` on a session watcher logs a warn and releases only that session (the client's next packet creates a new one); on a UDP listener it is logged and `clear_timer_cb()` restarts the watcher on its next tick, like the TCP accept watcher. Wildcard UDP listeners (D87–D90): before `bind()`, `udp_pktinfo_listen()` sets `IP_PKTINFO` on every worker's socket of a rule listening on `0.0.0.0` or `[::ffff:0.0.0.0]` (it reports `ipi_spec_dst`, the address to answer from: the destination for unicast, the receiving interface's address for broadcast and multicast; it also works for IPv4 datagrams on an AF_INET6 socket since 3.10), and only `IPV6_RECVPKTINFO` on `[::]` (D88: one cmsg per datagram; IPv4 clients get a v4-mapped `IPV6_PKTINFO` since 3.14, which carries the destination itself, so a subnet broadcast goes through the fallback below, while multicast and 255.255.255.255 destinations are not recorded; before 3.14 they get no cmsg and keep the old behavior). Success sets `forward_rule_t::udp_pktinfo` and attaches `udp_batch.ctrl[i]` to `in[i]` only (`attach_ctrl(0)`, which sets `in_ctrl`); failure logs one warn per rule (`rule N [udp] setsockopt IP_PKTINFO|IPV6_RECVPKTINFO failed (...): replies go out from the address the kernel chooses`) and that worker's rule behaves as before. Specific-address listeners set and attach nothing, so their path is unchanged. `udp_recv_ctrl()` stores the destination in a `udp_local_t` (IPv4 for a v4-mapped address; an IPv6 multicast destination is not recorded, a link-local one only if the client address has a scope id), and `udp_forward_batch()` copies it into `udp_pair_t::local` on every packet (D89: the latest destination wins; with several workers the reuseport hash includes the destination, so a client that switches destination usually gets another worker's session anyway). The old 24-byte receive buffer would not hold `UDP_GRO` plus a pktinfo (the kernel sets `MSG_CTRUNC`, and every packet would be dropped), so `udp_recv_ctrl_t` holds `UDP_GRO`, `IPV6_PKTINFO` and `IP_PKTINFO` together (96 bytes on 64-bit). `udp_cb()` copies the session's `local` into `rlocal[slot]` like `raddr`, and the flush builds every return entry's control data with `udp_ret_set_ctrl()` in a `udp_ret_ctrl_t` (`[UDP_SEGMENT][pktinfo]`, the pktinfo at `CMSG_SPACE(u16)` where the kernel looks for the next cmsg, `msg_control` pointing at whichever part is used; rebuilt for every entry because entries are reused across rules): `SOL_IP`/`IP_PKTINFO` with `ipi_spec_dst` for IPv4 and v4-mapped clients (all kernels; a v4-mapped `IPV6_PKTINFO` is ignored before 3.15), `IPV6_PKTINFO` for IPv6 clients with `msg_controllen` = `CMSG_LEN` (36: the kernel copies up to `sizeof(cmsghdr)+20` bytes of control data on its stack and `kmalloc`s anything larger, 15–30 ns per message), ifindex 0 (routing, or the client's scope id, picks the interface). Since a return entry may now carry a cmsg without `UDP_SEGMENT`, `udp_msg_gso()` checks that the first cmsg is `SOL_UDP` instead of testing `msg_controllen`, and `udp_send_split()` copies the pktinfo into every piece. A return entry whose pktinfo send fails with EINVAL, ENETUNREACH, ENODEV or EADDRNOTAVAIL (D90: the address was removed, is a subnet broadcast address, or is IPv6 AnyIP, a `local` route on `lo`, which the kernel refuses as an IPv6 source without freebind; IPv4 reports EINVAL before 5.4 and ENETUNREACH since, IPv6 EINVAL) is handled before the GSO errors by `udp_pktinfo_off()`: it strips the pktinfo from that entry and from the group's later entries to the same client (keeping `UDP_SEGMENT`), clears the session's `local` (found by client address like in `udp_gso_turn_off()`) until the client's next packet records it again, logs `[udp]sending to {client} from ADDR on listen fd N failed (...), letting the kernel choose the source address until the client sends again` at info once per rule (`rule_shared_t::pktinfo_logged`) and at debug after that, and the entry is resent and counted like any other; an EINVAL that was really a GSO error fails again and then takes the GSO path, so it costs that client its source address until its next packet but never turns GSO off because of a source address. With `--udp-gro` (U5, D41–D43; process-wide, command line only, off by default) every UDP listen and session socket gets `UDP_GRO` (`udp_gro_set()`): the kernel merges a burst of one flow arriving through a GRO-capable interface into one buffer and reports the segment size in a `SOL_UDP`/`UDP_GRO` cmsg (an `int`: read as u16 it is 0 on big-endian MIPS). `udp_gro_listen()` attaches the control buffers `udp_batch.ctrl[i]` to `in[i]` and `rin[i]` (`attach_ctrl(1)`) (shared by both like the slots) whenever one of that worker's listen sockets accepts the option (idempotent); if the first one fails (kernel before 5.0) it warns and clears `udp_gro`, so no socket ever has `UDP_GRO` while cmsgs are not parsed (a merged buffer would otherwise go out as one oversized datagram); later failures only log, once per rule (debug for a session socket). `udp_recv_ctrl()` walks the cmsgs (`UDP_GRO`, and the destination address of D87 below), copies the size into `gso[i]` and restores `msg_controllen` for every received entry (needed before the next `recvmmsg`); an entry with `MSG_CTRUNC` is dropped with a warn (review L4: the kernel writes `SO_TIMESTAMP`-like cmsgs before `UDP_GRO`, and reading a merged buffer as one datagram would forward it whole; enlarge `udp_recv_ctrl_t` if such options are ever enabled). `udp_batch_set_gso()` gives the matching send entry (`out_ctrl`/`rout_ctrl`) a `UDP_SEGMENT` cmsg (`cmsg_len` must be exactly `CMSG_LEN(sizeof(u16))`) only when the packet has more than one segment (without TX checksum offload, kernels before 6.11 return EIO even for one segment), so a merged packet is one `sendmmsg` entry that the kernel or the NIC splits into the original datagrams. `udp_send_group()` takes a `udp_send_ctx_t` and passes entries that `sendmmsg` must not get (GSO is off for that session and direction, or more than `udp_gso_cap()` segments: `udp_gso_max_segs` (64), since `UDP_MAX_SEGMENTS` is 64 before 6.9, 128 since and in Ubuntu's 6.8) and failed GSO entries to `udp_send_split()`, which sends one merged packet in pieces of at most that many segments, or datagram by datagram once GSO is off, through `udp_batch.seg` (musl pads must stay 0, like `out`). The fallback state is per session and direction (D45, `udp_pair_t::gso_off[2]`): inbound the context points at the session's `gso_off[0]` for the whole group; on the return path `udp_cb()` copies the session's `gso_off[1]` into `roff[slot]` and the flush into `rout_off[entry]` (no session pointer is kept, D36), because the listen socket checks each client's own route PMTU. EIO, EINVAL or EMSGSIZE on a GSO entry (no TX checksum offload before 6.11, or IPsec; a segment larger than the path MTU: EINVAL up to 6.13, EMSGSIZE since 6.14 and in Ubuntu's 6.8; too many segments) call `udp_gso_turn_off()`: it sets the flag (return path: the session is found again by the client address that `msg_name` points to, `raddr[j].inner` being `address_t`'s only data member, and the group's later entries to that client are switched too), adds 1 to `gso_fallback[dir]`, logs `[udp]GSO send from|to {client} on session|listen fd N failed (...)` at info for the first time per rule and direction (across all workers: `rule_shared_t::gso_logged`) and at debug after that (review L3), and the packet is resent datagram by datagram. An EINVAL on more than 64−⌈48/gso⌉ segments is first taken as the old-kernel limit (5.0–5.15 without the v5.16 fix count the IP/UDP headers, so 64 full segments always fail; review L1): `udp_gso_old_limit()` sets the process-wide `udp_gso_hdr_cap` and the packet is resent in smaller pieces without turning GSO off. Any other error (e.g. an ICMP error, consumed by that call) sends the packet once more as GSO and drops a piece that fails again; EAGAIN drops the rest of the group as before. With `--udp-gro`, `new_connected_udp_fd()` sets a session's SO_SNDBUF to `listen_fd_buf_size` when that is larger than `socket_buf_size`, past the cap when it can (D44): one inbound callback can hand a session everything queued on the listen socket (up to 64 merged packets, ~4 MiB), and a real NIC releases send-buffer memory only after transmission, so a smaller sndbuf turned bursts the listen buffer absorbs into EAGAIN drops (measured with a tbf qdisc holding the skbs; veth and lo orphan them at once); the cost is up to that much data queued per overloaded session in the egress qdisc (send-side memory is not in `udp_mem`). The batch limits (D35, D37) count entries, so with merged packets one loop pass can move ~4 MiB each way (review L5). `pkts`, `bytes` and `drop` count datagrams, `gro[dir]` the datagrams that arrived merged. Side effects: `UDP_GRO` on any socket turns on the kernel's `udp_encap_needed_key`, so every UDP packet the host receives gets a socket lookup in the GRO stage; merged packets use the overflow areas, so GRO traffic makes the ~4 MiB of overflow area resident. loopback never merges plain datagrams; only local GSO sends pass lo whole (since 5.11), which is how the tests produce merged packets. UDP sockets always get explicit buffers (U6, D38–D40): the listener `listen_fd_buf_size` (2 MiB, or `--udp-listen-buf`) through `set_udp_buf_size()`, each session `socket_buf_size` (1 MiB, or `--sock-buf`), per direction through `set_udp_buf_dir()` in `new_connected_udp_fd()`, forced only when `sock_buf_explicit` (with `--udp-gro` the send side may take `listen_fd_buf_size`, D44) (D38 revised: forced session buffers multiply with the session count; with 2 MiB sessions a 32-flow reverse flood lost 13% throughput and queued 28 ms instead of 0.55 ms, and on a 128 MB router a few full queues reach `net.ipv4.udp_mem[0]`, UDP's effective global receive limit, about 11 MiB there). `set_udp_buf_size()` tries `SO_SNDBUFFORCE`/`SO_RCVBUFFORCE` first, which need `CAP_NET_ADMIN` in the initial user namespace (the kernel checks `capable()`: root on the host has it, root in a user namespace does not) and are not capped by `net.core.rmem_max`/`wmem_max`; the first failure (EPERM) is logged at debug and remembered in the file-scope `udp_buf_force` (shared by both directions through `set_udp_buf_dir()`), so later UDP sockets use the plain options directly and a process without the capability spends no extra syscall per session (a relaxed `std::atomic<int>` shared by all workers; the debug line is written by the thread whose `exchange` clears it, so exactly once per process). A later plain `SO_RCVBUF`/`SO_SNDBUF` on a forced socket would shrink it back to the capped size, so re-set UDP buffers only through `set_udp_buf_size()`/`set_udp_buf_dir()`. The kernel stores twice the request, capped first by `rmem_max`/`wmem_max` (212992 before Linux 6.18, 4 MiB since) when not forced: without the capability on an untuned older kernel both kinds of socket get 416 KiB; with it the listener gets 4 MiB per direction (what 6.18+ gives anyway) and sessions keep 416 KiB unless `--sock-buf` is given. After setting the listener's buffers `start_forward_rule()` reads both back and logs one info line per UDP rule when either is below twice the request. TCP sockets never use the FORCE options.
- Connection lifetime is LRU-based per rule. Each `forward_rule_t` owns `conn_manager_tcp_t`, `conn_manager_udp_t`, and their `lru_collector_t` state; each worker's `clear_timer_cb()` periodically removes inactive pairs across its rules. Time comes from the worker's `loop_clock_t::now()` (ms; `lru_collector_t::clock` points at it): libev's monotonic clock as cached for the current loop iteration (`my_ev_mono_now()` reads that loop's `mn_now`, which libev refreshes from `CLOCK_MONOTONIC` after every `epoll_wait`), so nothing reads the clock per event and wall-clock steps (NTP, `date -s`) do not change idle timeouts; the ms value is cached (`last_bits`/`last_ms`, per worker) by the bit pattern of `mn_now`, so soft-float targets (mips24kc, arm) do the double conversion once per iteration. Call it only on the thread that runs that loop. `lru_collector_t` is an intrusive doubly linked list: `tcp_pair_t`/`udp_pair_t` inherit `lru_node_t` (`prev`/`next`/`ts`), so linking, moving and unlinking allocate nothing and need no lookup. Pairs come from `obj_pool_t` (`tcp_pair_pool`, `udp_pair_pool`): slabs of 64 objects that are never freed and a LIFO free list; `get()` constructs the object in place, so a reused pair starts with null LRU links, zeroed watchers and no buffers. A pair is linked by `lru.new_key()` right after `get()` and unlinked only in the managers' `erase()`/`erase_closed()`, before `put()` returns it to the pool. The LRU list is the only list of a manager's pairs: `remote_sweep()` walks it (taking `next` before releasing the current pair), and `lru.size()` is the connection count used in logs and for `max_conn_num`. The collector's sentinel `head` points to itself, so its copy operations are deleted: it cannot live in a container that relocates elements (e.g. a growing `vector`). `lru_collector_t::update()` moves a pair to the front only when its timestamp is at least `lru_move_interval` (1 s) old, so a pair can be cleared up to 1 s before its exact idle timeout.
- Watchers reach their owner through `watcher->data` (`EV_COMMON` in `my_ev_common.h` is only `void *data;`): the `forward_rule_t` for the listener watchers, the `tcp_pair_t` for both watchers of a TCP pair (`tcp_cb()` tells the side by comparing `watcher` with `&pair.local.ev`), the `udp_pair_t` for a UDP session; fds are plain `int`s (`tcp_info_t::fd`, `udp_pair_t::fd`), with no lookup table. The managers' `erase()`/`erase_closed()` release a pair in a fixed order: `ev_io_stop()` each of its watchers, then `close()` its fds, then return its buffers and the pair to the pools. `ev_io_stop()` also discards the watcher's event still pending in the current loop iteration, so no callback can reach a released pair, and a later callback of the same iteration may reuse the fd numbers (e.g. `accept4()`) and, because the pool is LIFO, normally the pair's memory too. Do not return a pair to the pool, or start reusing its memory, before both watchers are stopped; `obj_pool_t::put()` checks this in every build, including release (X1, D30): if a watcher of the returned pair is still active or pending it logs `log_fatal` and calls `abort()` (four field reads and one branch per release). libev's own `corrupted watcher` assertion only catches a watcher list that loops onto itself, not longer loops or a stale watcher on another fd number. In ASan builds (`__SANITIZE_ADDRESS__`) free pool objects and blocks are poisoned, so a callback reaching a released pair is reported unless the pair was already reused, which is the common case for a missing `ev_io_stop()`: the next `accept4()` of the same iteration usually gets the pair back and libev's `corrupted watcher` assertion fires instead (keep `assert()` enabled in test builds, and `DEBUG_ASSERT` too: `make test` runs the `-assert` builds). A watcher that gets a new fd must go through `ev_io_init()` (or `ev_io_set()`): its `EV__IOFDSET` flag makes libev re-register the fd with epoll even when the same fd number was closed earlier in this iteration with the same event mask (libev still caches the old mask), and with the local `fd_reify` patch (T13) the fd is ADDed directly instead of MOD (ENOENT) then ADD. Event changes on the fd a watcher already has must not go through `ev_io_init()`: `tcp_cb()` stops the watcher, changes `events` and restarts it; an `ev_io_init()` on a still-registered fd would cost an ADD (EEXIST) plus a MOD.
- Counters (O1, D25–D27, D63): SIGUSR1 (an `ev_signal` on the main thread's default loop, started in `main()`; earlier versions exited on it) runs `sigusr1_cb()`, which posts `worker_msg_stats` to every worker (`stats_request()`; a SIGUSR1 that arrives while a round is outstanding is merged into one more round after it; if a round is still incomplete after 5 s, `main_timer_cb()` logs one warn naming the workers that did not answer and keeps waiting, review L-5; like the stats lines it goes through `mylog_unfiltered`, so it is written at every `--log-level` except 0, D112). Each worker's `worker_stats()` copies its counters, the per-rule current, half-closed and session-table counts and its pool counts into a `worker_stats_t` between two callbacks of its loop and hands it back under `stats_mutex` with `ev_async_send` on the main loop; when all have answered, `stats_print()` writes, under `flockfile(stdout)` so that worker log lines cannot split the group, with more than one worker first one `stats worker W: tcp_conns= tcp_total= udp_sessions= udp_total=` line per worker (W from 0), then for each rule a `stats rule N tcp:` and/or `udp:` line and then one `stats pool:` line, both summed over the workers (`scratch` up to N), with `mylog_unfiltered` (written at every `--log-level` except 0), then `fflush`es stdout; with one worker the output is byte-identical to earlier versions, and the pool line still ends the group. Only cumulative counters are updated on the hot path: `conn_manager_tcp_t::total`/`bytes[2]`/`splice_bytes[2]` (the part of `bytes` written from a pipe)/`splice_fallback` (reads that wanted a pipe but got none, D49) and `conn_manager_udp_t::total`/`pkts[2]`/`bytes[2]`/`drop[2]` (index 0 client→upstream, 1 upstream→client; bytes and packets are counted per datagram that `sendmmsg()` sent, `drop` per datagram a failed call dropped, any errno (an EAGAIN drops the rest of the group: inbound the session's batch, U3; on the return path the rule's part of the return batch, U4; return-path counters change when the batch is flushed, at the latest before the loop blocks); `total` is incremented next to `lru.new_key()`), plus `tcp_buf_pool_t::alloc`, `tcp_pipe_pool_t::alloc` and `obj_pool_t::slabs`, which change only on the pools' `malloc()`/`free()` or a pipe's creation and close. The `tcp:` line ends with `up_splice`/`down_splice`/`splice_fallback`, the `stats pool:` line with `pipes alloc/held/free/scratch resize_fail` (both appended; `resize_fail` was added after them by B3, so older positional parsers still read the leading fields). With `--udp-gro` (D42, only then) the `udp:` line ends with `up_gro`/`down_gro` (`conn_manager_udp_t::gro[2]`, datagrams that arrived merged, counted at receive after the `MSG_TRUNC` check) and `up_gso_fallback`/`down_gso_fallback` (`gso_fallback[2]`, sessions that turned GSO off in that direction); without it the line is unchanged. Current connections come from `lru.size()`; half-closed pairs (`local.eof||remote.eof`) and blocks held by directions are counted when the signal arrives, by walking each rule's LRU (about 55 ns per pair with cold caches, 1–2 ms for 20000 pairs). The worker takes its snapshot between other callbacks, where `alloc == held + free + scratch` for both the blocks and the pipes, each object pool's `slabs*64 - free` equals the pairs in all of its worker's rules' LRUs, and each rule's `sessions.cnt` equals its UDP `lru.size()`; `stats_print()` `DEBUG_ASSERT`s these per worker only after flushing the lines, so a violation leaves the numbers in the log (the summed lines hold them too, since they are sums). Put a new counter in the per-rule manager (the managers belong to the worker's rule runtimes).

## Key Directories

- `.`: Main project sources and hand-written build file.
- `libev/`: Vendored libev snapshot and compatibility files. `.gitattributes` marks this directory as vendored. Maintenance scripts live here too. The snapshot is libev 4.24 plus later CVS changes (`libev/Changes` rev 1.315), with two local patches that affect Linux builds. T13 (D24): `fd_reify()` in `libev/ev.c` passes old mask 0 to the backend for an fd whose watcher was (re)set with `ev_io_set()` (`EV__IOFDSET`) in this iteration, so epoll ADDs it directly; upstream sends MOD first when the fd number was closed and reused in the same iteration (the cached mask is the old fd's), which fails with ENOENT before the ADD. The patch is only valid for epoll: poll/select, kqueue, port and libev ≥ 4.31's io_uring use the old mask to remove the old registration. `my_ev.cpp` fails the build if the patch marker `TPM_LIBEV_FD_REIFY_PATCH` is missing or another backend is compiled in. `update_ev_c` only re-embeds `ecb.h` and keeps the patch; when importing a newer libev, re-apply it (limited to `backend == EVBACKEND_EPOLL` if other backends are enabled) or drop it together with the check. T14: `epoll_poll()` in `libev/ev_epoll.c` maps EPOLLERR/EPOLLHUP only to the events the fd wants (READ|WRITE when it wants none, so libev's lazy DEL of a mask-0 fd still happens even if the fd reports only EPOLLERR: TCP always adds IN and OUT to ERR/HUP, a UDP socket with a pending ICMP error does not); upstream maps them to both, so an fd waiting only for READ that gets HUP (after our `SHUT_WR`, the peer's FIN) costs an `EPOLL_CTL_MOD` to the mask the kernel already has (for a non-zero mask the kernel registration always equals it, and epoll reports only registered IN/OUT bits). `my_ev.cpp` fails the build if its marker `TPM_LIBEV_EPOLL_HUP_PATCH` is missing; re-apply it when importing a newer libev.

## Code Conventions & Common Patterns

- Style is pragmatic C-with-classes C++11: global process state, `struct` data holders, `using namespace std`, C socket APIs, `char*`/fixed buffers, and manual lifecycle management.
- Naming is mostly `snake_case`; types commonly end in `_t` (`address_t`, `tcp_pair_t`, `lru_collector_t`). The parsed rules are `app_config.rules` (read-only after startup); runtime forwarding state lives in each worker's `rules` (`worker_t`, M1); each `forward_rule_t` owns its listener fds and TCP/UDP managers.
- Keep networking nonblocking: create sockets with `SOCK_NONBLOCK|SOCK_CLOEXEC` passed to `socket()` / `accept4()` instead of a follow-up `fcntl` (`setnonblocking()`). Use `set_buf_size()` (on TCP sockets only when `sock_buf_explicit`), `set_udp_buf_size()` for UDP sockets, and `close()`; once a pair exists, its fds are closed only by the managers' `erase()`/`erase_closed()`, after its watchers are stopped.
- Logging: `mylog(level, ...)` evaluates its level expression once and checks it before calling `log0()`, so arguments of filtered messages are not evaluated; `log0()` itself does not check `log_level`. `mylog_unfiltered(level, ...)` skips the check except at `--log-level 0`; only the SIGUSR1 stats and the warn for a late stats round use it (D26, D112). `log0()` is declared with `__attribute__((format(printf,5,6)))`, so `-Wformat` checks every `mylog` call. It formats the whole line into a stack buffer and writes it with one `fwrite` (the timestamp and each level's `color[time][LEVEL]` prefix are formatted once per second into `thread_local` function-local statics (M2, one cache per thread, about 1 KiB), so the main thread and the worker threads may log, each line one `fwrite` under the stdio lock (lines longer than the 1 KiB stack buffer are written in parts under `flockfile`); the DNS threads do not log and hand errors back through `dns_result_cb()`; the timestamp uses `localtime_r` because glibc's `localtime()` re-checks `/etc/localtime` on every call; `enable_log_color` is not part of the cache key, so it must not change once `log0()` has run: only the pre-scan at the top of `process_arg()` sets it, and the two earlier `log0()` calls, in `main()` when `/dev/null` cannot be opened for a closed fd 0–2 and when `ev_default_loop()` fails, exit immediately). stdout is flushed per line only on a tty (`stdout_is_tty` is a file-scope static set before `main()`: as a function-local static of `log0()` its first initialization would run on whichever thread logs first, under a `__cxa_guard` that does not lock in static glibc<2.34 builds such as `cross2`/`cross3`); otherwise it stays fully buffered (4 KiB with glibc, 1 KiB with musl) and is written when the buffer fills, by the main thread's `main_timer_cb()` every `timer_interval` (400 ms, for the lines of every thread), and by `myexit()`, so lines written right before an abort, an unhandled signal, or SIGKILL can be lost.
- Addresses: connections keep the client address as `address_t` (`tcp_pair_t::addr`, `udp_pair_t::adress`) and format it only inside `mylog` arguments with `get_str()`, so filtered lines and the per-packet UDP path do no formatting. `get_str()` returns one static buffer: it is `thread_local` (M2), so use it at most once per `mylog` call on the calling thread; otherwise `to_str()` into a local `char[max_addr_len]`. `to_str()` hand-formats IPv4, v4-mapped IPv6 (`::ffff:a.b.c.d`, how IPv4 clients of a dual-stack `[::]` listener appear) and the port (no `sprintf`); other IPv6 goes through `inet_ntop`. `to_str()` must not change `errno`: a `mylog` call may evaluate `get_str()` before `get_sock_error()`.
- Error handling uses `mylog(level, ...)`, `myexit()`, and `assert()` for invariants. Invariants checked per event, per packet or per connection (the callbacks, `tcp_accept_one()`, `select_remote_index()`, `lru_collector_t`, the managers' `erase()`, `address_t::get_len()`/`from_sockaddr()`/`to_str()`) use `DEBUG_ASSERT()` (`common.h`): `assert()` only when `ENABLE_DEBUG_ASSERT` is defined (`make all OPT=-DENABLE_DEBUG_ASSERT`, i.e. the `-assert` builds that `make test` runs, and `make fast`/`make debug`), otherwise `((void)sizeof(!(x)))`, so `make all` and `make release` compile them out. The expression must have no side effects (release builds do not evaluate it, and no compiler warns) and no lambda. Use it only for internal invariants, never to validate input: in a release build a violated check is undefined behaviour instead of an abort, either a crash without a message (e.g. `erase(end())` in the UDP manager) or silent corruption (a leaked block and lost data in `tcp_cb()`, cross-talk between pairs). `ENABLE_DEBUG_ASSERT` together with `NDEBUG` is a `#error`, because it would silently drop every assert; zig defines `NDEBUG` at `-O1` and above, so the `docker/build.sh cross` compile check builds no asserts at all. Release builds (`make all`, `make release`) deliberately do not define `NDEBUG` (X1, D28): after T12 that would only remove libev's checks (nothing measurable on any workload), and without libev's `corrupted watcher` assertion a missing `ev_io_stop()` whose pair and fd number are reused turns from an abort into a livelock (`fd_reify()` walks a looped watcher list forever: 100% CPU, SIGTERM never handled, the process does not exit). Do not add `NDEBUG` to `FLAGS` or the release targets; a release built with zig needs `-UNDEBUG`. Startup and config checks keep plain `assert()`. Fatal setup errors usually log `log_fatal` then exit; runtime network errors usually log and close/erase the affected connection. `myexit()` flushes stdout and calls `_exit()`: no static destructors or `atexit` handlers run, because the detached DNS threads may still be blocked on `dns_cv` (glibc's `pthread_cond_destroy` would wait for it forever) and other threads may still run, so do not put shutdown work in destructors. A worker may call `myexit()` on a fatal error (the whole process exits); SIGTERM/SIGINT first stop the workers (`workers_stop()`, M6).
- Async work is libev-based only: `ev_io_init/start/stop`, `ev_timer`, `ev_signal`, `ev_async`, `ev_prepare` (the UDP return-batch flush), `EV_READ`, and `EV_WRITE`. A loop belongs to one thread: the default loop to the main thread (signals only there), each `ev_loop_new` loop to its worker; across threads use only `ev_async_send` (`worker_post()`, the stats and DNS results). Watchers that live in zero-filled memory (`worker_t`, BSS) get their callback and parameters assigned directly instead of `ev_*_init` macros, which add `-Wstrict-aliasing` warnings. When changing watcher events on the same fd, existing code stops the watcher, changes `events` (no `ev_io_init`, T13), then restarts it.
- Avoid introducing new allocation-heavy abstractions in hot paths. TCP data goes through `tcp_scratch` and `tcp_buf_pool` blocks (or `tcp_pipe_scratch` and `tcp_pipe_pool` pipes for splice) and connection objects through `obj_pool_t`, so TCP forwarding and TCP connection setup do not call `malloc()` once the pools have grown to the peak (free blocks beyond 64 are freed and allocated again in the next backpressure burst); neither does a new UDP session once its rule's session table has grown to the peak. UDP reads packets in both directions into the worker's `udp_batch` (the return path shares its slots, D36).
- `libev/ev_wrap.h` is generated by `libev/update_ev_wrap`; do not hand-edit generated or vendored libev files unless the change is explicitly about the embedded event loop.

## Runtime/Tooling Preferences

- Required language/toolchain: C++11 with `g++`/compatible compiler and GNU Make-style `makefile`.
- No Node, Bun, Python package manager, or dependency lockfile is used for the project build. Go (tests, `bench/fwdbench`) and Python 3 (bench summaries) use only their standard libraries.
- libev is always embedded (`my_ev.cpp` includes `ev.c`) and built with the epoll backend only; `event_loop()` logs the active backend (`event backend: epoll`) at startup.
- Linux is the only supported platform (glibc distributions and OpenWRT/musl; deployed directly on hosts). Windows/macOS/FreeBSD/Cygwin targets and code paths were removed; do not add non-Linux fallbacks. On a macOS dev machine, build and test through `docker/build.sh` / `make test`.
- Keep `libev/` treated as third-party vendored code. Prefer changing project wrapper/configuration files before modifying libev internals; the only local changes that affect Linux builds are the `fd_reify()` patch (T13) and the `epoll_poll()` ERR/HUP mapping (T14).

- Known defects are wrapped in `xfail(t, "<id>", ...)` with IDs from the optimization roadmap (none at present). The body asserts the correct behavior; once a fix lands the test reports XPASS and fails until the `xfail` wrapper is removed.
- Listener readiness (`listening()`/`listenFD()`), the accept-queue length in `listenFull` and the SYN_SENT count in `synSentTo` come from `NETLINK_SOCK_DIAG` queries, never from reading `/proc/net/tcp`: next to `TestTCPMaxConn` (about 80k sockets) one read of that file takes seconds and readiness waits time out.

- Benchmarks: `make bench` (= `bench/run.sh`) runs the loopback benchmark and syscall counts in Docker (forwarder CPU0, client CPU2-3, backends CPU4-5) and writes `bench/results/<stamp>/`. tinymapper runs without `CAP_NET_ADMIN` in every stage by default (UDP buffers capped at 416 KiB, comparable with the baselines; the `--privileged` syscount/prof stages drop it through `TM_NOCAP`); `CAP_ADD=NET_ADMIN` gives it to every stage, and a `+nocap` forwarder name (`tinymapper@<ref>+nocap`) runs the same binary without it through `setpriv` for same-batch comparisons (U6). A `+gro` forwarder suffix (composable with `+nocap`) starts the same binary with `--udp-gro` (U5); `+nosplice` starts it with `--disable-splice` (B2), `+t<N>` with `--threads N`, pinned to `FWD_CPUS2` (0,1, like realm-2c) for N ≥ 2 with the CPU accounting over that set and each worker's connection and session counts recorded as `tm_w<N>` (M2), and `+nonroot` (any forwarder, e.g. `realm-1c+nonroot`) starts it through `setpriv` as the dedicated uid `FWD_UID` (4242) without capabilities, so `fs.pipe-user-pages-soft` applies to it alone (container root lacks `CAP_SYS_RESOURCE` too, but uid 0 is shared with every root process of the VM). `+aff` starts tinymapper with `--cpu-affinity` (M5, composable with `+t<N>`); `VETH_RPS=<hex mask>` (`TOPO=veth` only) sets `rps_cpus` on the forwarder-side veths f0/f1, which makes the forwarder's inbound protocol processing run on the RPS CPU chosen by flow hash, emulating a multi-queue card with queue interrupts on the worker CPUs (recorded in `topo.txt`; no RFS, `net.core.rps_sock_flow_entries` is VM-global); `IPI_STATS=1` adds per row `irq` (IPI and NET_RX deltas from `/proc/interrupts` and `/proc/softirqs`, VM-wide; loopback containers then get `--security-opt systempaths=unconfined`, since Docker masks `/proc/interrupts`) and `tm_aff` (each thread's `Cpus_allowed_list`); `ALT=1` reverses the forwarder order on even rounds and `WARMUP=1` adds a discarded rep-0 run. With RPS, compare CPU per operation by the forwarder CPUs' busy time from `/proc/stat`: softirq that RPS runs on an idle CPU is charged to the idle task, not to the forwarder process. TCP rows record the SIGUSR1 `tcp:` and `pool:` fields (`tm_tcp`, `tm_pool`), so check `splice_fallback == 0` before trusting a splice result. `tcp_bulk_<N>[_stall]` runs `fwdbench bulk`: N connections each writing 64 KiB chunks through the forwarder to `fwdbench sink` (port 9001, verifies the content), client `SO_SNDBUF` fixed at `BULK_SNDBUF` (32768); `_stall` makes the sink pause `BULK_STALL` (1) seconds first so every direction backs up in the forwarder. 2000 such connections push the 8 GB Docker VM over `tcp_mem` (about 735 MB), so their throughput mostly measures memory pressure; judge them by errors and fallback counts. `GATE_LOCK` makes every stage wait while that lock file exists. loopback never does GRO, so `TOPO=veth` (U5, D43) builds three network namespaces in the (then `--privileged`) container, client → forwarder → backend over two veth pairs with the same CPU pinning; the forwarder-side veths have `gro on`, `gro_flush_timeout` 50 µs and `napi_defer_hard_irqs` 2 (emulating NIC interrupt coalescing) and the peers `tso off` (`veth_skb_is_eligible_for_gro`), so a `UDP_GRO` socket gets merged packets (about 46 × 1400 B); the forwarder's inbound softirq then runs on the senders' CPUs and its outbound packets' receive on CPU0, so compare CPU per forwarded datagram (`docs/bench/u5/ab.py`) rather than throughput, which iperf3 3.16 caps at both ends (`bench/BASELINE.md` §6). With tinymapper as the forwarder, syscount counts UDP per datagram from the SIGUSR1 `up_pkts+down_pkts` (a GSO send adds 1 to `OutDatagrams`). The tool images are `tinymapper-bench:2`/`tinymapper-bench-prof:2` (iproute2, ethtool). `FWDS="tinymapper@4acc876 tinymapper" bench/run.sh` compares a commit with the working tree; `QUICK=1` is a smoke run; `bench/host.sh` runs the same workloads on real client/forwarder/server hosts over ssh. Run benchmarks with the Docker VM otherwise idle. Baselines and procedures are in `bench/BASELINE.md`.
