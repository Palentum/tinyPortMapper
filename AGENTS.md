# Repository Guidelines

## Project Overview

tinyPortMapper (`tinymapper`) is a lightweight C++11 TCP/UDP port mapping and forwarding utility. It supports single-rule CLI startup and config-file startup with multiple forwarding rules in one process, forwarding IPv4, IPv6, and 4-to-6 / 6-to-4 traffic. The data plane is event-driven and embeds `libev` directly into the binary.

## Architecture & Data Flow

- `main.cpp` owns the application flow: CLI parsing, socket setup, libev watcher registration, signal handling, TCP/UDP callbacks, and connection cleanup.
- `process_arg()` parses single-rule CLI options (`-l`, `-r`, `-t`, `-u`) or `-c/--config <path>` into `app_config.rules`; log, color, socket-buffer, and `--disable-tcp-nodelay` options remain process-wide.
- `event_loop()` materializes `forward_rule_t` objects from `app_config`, creates only the enabled TCP/UDP listeners for each rule, registers `ev_io` accept/read watchers with `watcher->data` pointing at the owning rule, starts a periodic `ev_timer`, then calls `ev_run()`.
- TCP flow: `tcp_accept_cb()` accepts the pending local clients of one `forward_rule_t`, calling `tcp_accept_one()` until `accept4(SOCK_NONBLOCK|SOCK_CLOEXEC)` returns EAGAIN (silently) or `max_accept_per_round` (8) clients were taken in this loop iteration (the listener must stay nonblocking, since the last `accept4()` of a round normally returns EAGAIN); any other accept failure and an immediate upstream `connect()` failure (EADDRNOTAVAIL first scans the whole ephemeral port range) also end the round, while `max_conn_num`, a failed connection-object allocation and an upstream `socket()` failure only drop that client and move on (if `accept4()` fails with anything but EAGAIN/EINTR/ECONNABORTED, e.g. EMFILE/ENFILE/ENOMEM or an LSM denial, the client stays in the backlog, so the rule's accept watcher is stopped and `clear_timer_cb()` restarts it on its next tick; an `EV_ERROR` on the accept watcher, e.g. a failed epoll re-add, is logged and retried the same way), takes a `tcp_pair_t` from `tcp_pair_pool` (if a new slab cannot be allocated, only that client is closed with a warn, before anything is sent to the upstream or the roundrobin index advances), opens a nonblocking remote socket to that rule's `remote_addr` (if `socket()` fails, e.g. EMFILE, only that client is closed and the pair goes back to the pool) and starts a nonblocking `connect()` (an immediate failure other than EINPROGRESS, e.g. ENETUNREACH or EADDRNOTAVAIL, closes the client with a warn), fills the `tcp_pair_t` with both fds and points both watchers' `data` at it, then `tcp_cb()` relays data between the two endpoints while toggling `EV_READ` / `EV_WRITE` watchers for backpressure. Every `recv()` reads up to `max_data_len_tcp` (64 KiB) into the loop-wide `tcp_scratch` block; if `send()` takes all of it the block stays scratch for the next `recv()`, otherwise (partial or failed send, or upstream still connecting; a send error is left to the write branch, which closes the pair) the block itself is handed to that direction (`tcp_info_t::buf`, with `begin`/`data_len`; no copy), reading from the source stops, and the next `recv()` first takes another block from `tcp_buf_pool`. A direction holds a block only while it has unsent data (`buf` is non-null exactly when `data_len` is non-zero): the write branch returns it once drained, and the managers return held blocks when they release a pair. The pool keeps at most `tcp_buf_pool_max_free` (64) free blocks and `free()`s the rest; an empty pool `malloc()`s a new block. If that `malloc()` fails (only under `RLIMIT_DATA`/`RLIMIT_AS` or `vm.overcommit_memory=2`; with default overcommit, exhaustion means the OOM killer), the pair whose `recv()` needed the block is closed with a warn: whichever pair reads next, not necessarily the one holding memory, and the read branch runs first even when that side could have drained its own held block by writing. Other allocation failures still abort the process: libev growing its fd array for a new fd peak (`ev_realloc`), a UDP `adress_to_info` node (`std::bad_alloc`), the DNS thread's queues. User-space memory therefore follows backpressure: an idle pair is about 0.3 KB, but each direction whose destination is slower than its source holds a whole 64 KiB block until it drains (at most 2 × 64 KiB per pair, with no global cap besides `max_conn_num`). Both sides run with `TCP_NODELAY` unless `--disable-tcp-nodelay` is given: the TCP listener sets it once and accepted sockets inherit it, the upstream socket sets it before `connect()`. The TCP listener calls `listen()` with `listen_backlog` (65535), which the kernel caps at `net.core.somaxconn` (4096 by default since Linux 5.4, 128 before); the libc `SOMAXCONN` macro is not used because musl (and glibc before 2.31) define it as 128. TCP socket buffers are left to kernel autotuning: `SO_SNDBUF`/`SO_RCVBUF` are set only when `--sock-buf` is given (`sock_buf_explicit`), then once on the TCP listener before `listen()` (accepted sockets inherit the size and the `SOCK_*BUF_LOCK` bits, so setting it on the listener unconditionally would disable autotuning for every client) and on the upstream socket before `connect()`. Connect state: while the upstream is CONNECTING (`tcp_info_t::connected==0`) its watcher waits for `EV_READ|EV_WRITE` and nothing is sent or shut down on it; a writable-only report means connected, a readable report is checked with `getsockopt(SO_ERROR)`, and an error (refused, unreachable, or the kernel's SYN timeout ETIMEDOUT; there is no separate connect timer, only the TCP idle timeout) closes the pair with a warn. Client data read meanwhile (one 64 KiB block) is held and sent once the upstream connects, before anything is read from the upstream. Half-close: an EOF from one side (`tcp_info_t::eof`) is forwarded as `shutdown(SHUT_WR)` on the other side while the opposite direction keeps flowing; if the upstream is still connecting the shutdown waits until it connects, because `shutdown()` on a SYN_SENT socket aborts the connect. The pair is released once both sides have sent EOF, or on any recv/send/shutdown error, or when one of its watchers gets `EV_ERROR` (libev's `fd_kill` after `epoll_ctl` fails with anything but ENOENT/EEXIST/EPERM, in practice an `EPOLL_CTL_ADD` beyond `fs.epoll.max_user_watches` (ENOSPC) or ENOMEM, for a new fd or for an established pair's fd that libev deleted from epoll while backpressure had dropped its event mask to 0 and now re-adds; libev has already stopped that watcher): a warn, and only that pair is released.
- UDP flow: `udp_accept_cb()` receives the first packet from a client address on one rule's listener, creates one connected UDP socket to that rule's `remote_addr` and takes a `udp_pair_t` from `udp_pair_pool` (if a new slab cannot be allocated, the socket is closed and the packet dropped with an info line), stores it in the rule's `conn_manager_udp`, then `udp_cb()` sends responses back to the original listener/client with `sendto()`. An `EV_ERROR` on a session watcher logs a warn and releases only that session (the client's next packet creates a new one); on a UDP listener it is logged and `clear_timer_cb()` restarts the watcher on its next tick, like the TCP accept watcher. UDP sockets always get explicit buffers: the listener `listen_fd_buf_size` (2 MiB), each session `socket_buf_size` (1 MiB, or `--sock-buf`).
- Connection lifetime is LRU-based per rule. Each `forward_rule_t` owns `conn_manager_tcp_t`, `conn_manager_udp_t`, and their `lru_collector_t` state; `clear_timer_cb()` periodically removes inactive pairs across all rules. Time comes from `get_current_time()` (ms): libev's monotonic clock as cached for the current loop iteration (`my_ev_mono_now()` reads the default loop's `mn_now`, which libev refreshes from `CLOCK_MONOTONIC` after every `epoll_wait`), so nothing reads the clock per event and wall-clock steps (NTP, `date -s`) do not change idle timeouts; the ms value is cached by the bit pattern of `mn_now`, so soft-float targets (mips24kc, arm) do the double conversion once per iteration. It dereferences `ev_default_loop_ptr`: call it only on the event-loop thread, after `ev_default_loop()`. `lru_collector_t` is an intrusive doubly linked list: `tcp_pair_t`/`udp_pair_t` inherit `lru_node_t` (`prev`/`next`/`ts`), so linking, moving and unlinking allocate nothing and need no lookup. Pairs come from `obj_pool_t` (`tcp_pair_pool`, `udp_pair_pool`): slabs of 64 objects that are never freed and a LIFO free list; `get()` constructs the object in place, so a reused pair starts with null LRU links, zeroed watchers and no buffers. A pair is linked by `lru.new_key()` right after `get()` and unlinked only in the managers' `erase()`/`erase_closed()`, before `put()` returns it to the pool. The LRU list is the only list of a manager's pairs: `clear_remote_index()` walks it (taking `next` before releasing the current pair), and `lru.size()` is the connection count used in logs and for `max_conn_num`. The collector's sentinel `head` points to itself, so its copy operations are deleted: it cannot live in a container that relocates elements (e.g. a growing `vector`). `lru_collector_t::update()` moves a pair to the front only when its timestamp is at least `lru_move_interval` (1 s) old, so a pair can be cleared up to 1 s before its exact idle timeout.
- Watchers reach their owner through `watcher->data` (`EV_COMMON` in `my_ev_common.h` is only `void *data;`): the `forward_rule_t` for the listener watchers, the `tcp_pair_t` for both watchers of a TCP pair (`tcp_cb()` tells the side by comparing `watcher` with `&pair.local.ev`), the `udp_pair_t` for a UDP session; fds are plain `int`s (`tcp_info_t::fd`, `udp_pair_t::fd`), with no lookup table. The managers' `erase()`/`erase_closed()` release a pair in a fixed order: `ev_io_stop()` each of its watchers, then `close()` its fds, then return its buffers and the pair to the pools. `ev_io_stop()` also discards the watcher's event still pending in the current loop iteration, so no callback can reach a released pair, and a later callback of the same iteration may reuse the fd numbers (e.g. `accept4()`) and, because the pool is LIFO, normally the pair's memory too. Do not return a pair to the pool, or start reusing its memory, before both watchers are stopped; `obj_pool_t::put()` checks this in every build, including release (X1, D30): if a watcher of the returned pair is still active or pending it logs `log_fatal` and calls `abort()` (four field reads and one branch per release). libev's own `corrupted watcher` assertion only catches a watcher list that loops onto itself, not longer loops or a stale watcher on another fd number. In ASan builds (`__SANITIZE_ADDRESS__`) free pool objects and blocks are poisoned, so a callback reaching a released pair is reported unless the pair was already reused, which is the common case for a missing `ev_io_stop()`: the next `accept4()` of the same iteration usually gets the pair back and libev's `corrupted watcher` assertion fires instead (keep `assert()` enabled in test builds, and `DEBUG_ASSERT` too: `make test` runs the `-assert` builds). A watcher that gets a new fd must go through `ev_io_init()` (or `ev_io_set()`): its `EV__IOFDSET` flag makes libev re-register the fd with epoll even when the same fd number was closed earlier in this iteration with the same event mask (libev still caches the old mask), and with the local `fd_reify` patch (T13) the fd is ADDed directly instead of MOD (ENOENT) then ADD. Event changes on the fd a watcher already has must not go through `ev_io_init()`: `tcp_cb()` stops the watcher, changes `events` and restarts it; an `ev_io_init()` on a still-registered fd would cost an ADD (EEXIST) plus a MOD.
- Counters (O1, D25–D27): SIGUSR1 (an `ev_signal` started in `main()`; earlier versions exited on it) runs `sigusr1_cb()`, which writes, for each rule, a `stats rule N tcp:` and/or `udp:` line and then one `stats pool:` line with `mylog_unfiltered` (written at every `--log-level` except 0), then `fflush`es stdout. Only cumulative counters are updated on the hot path: `conn_manager_tcp_t::total`/`bytes[2]` and `conn_manager_udp_t::total`/`pkts[2]`/`bytes[2]`/`drop[2]` (index 0 client→upstream, 1 upstream→client; bytes and packets are counted when `send()`/`sendto()` succeeds, `drop` when it fails, any errno; `total` is incremented next to `lru.new_key()`), plus `tcp_buf_pool_t::alloc` and `obj_pool_t::slabs`, which change only on the pools' `malloc()`/`free()`. Current connections come from `lru.size()`; half-closed pairs (`local.eof||remote.eof`) and blocks held by directions are counted when the signal arrives, by walking each rule's LRU (about 55 ns per pair with cold caches, 1–2 ms for 20000 pairs). libev runs the callback between other callbacks (the signal handler only marks the signal pending and wakes the loop through the eventfd), where `alloc == held + free + scratch`, each object pool's `slabs*64 - free` equals the pairs in all rules' LRUs, and each rule's `adress_to_info.size()` equals its UDP `lru.size()`; it `DEBUG_ASSERT`s these only after flushing the lines, so a violation leaves the numbers in the log. Put a new counter in the per-rule manager (P4 moves the managers into `worker_t`); splice and GSO fallback counters come with P3/P2.

## Key Directories

- `.`: Main project sources and hand-written build file.
- `libev/`: Vendored libev snapshot and compatibility files. `.gitattributes` marks this directory as vendored. Maintenance scripts live here too. The snapshot is libev 4.24 plus later CVS changes (`libev/Changes` rev 1.315), with two local patches that affect Linux builds. T13 (D24): `fd_reify()` in `libev/ev.c` passes old mask 0 to the backend for an fd whose watcher was (re)set with `ev_io_set()` (`EV__IOFDSET`) in this iteration, so epoll ADDs it directly; upstream sends MOD first when the fd number was closed and reused in the same iteration (the cached mask is the old fd's), which fails with ENOENT before the ADD. The patch is only valid for epoll: poll/select, kqueue, port and libev ≥ 4.31's io_uring use the old mask to remove the old registration. `my_ev.cpp` fails the build if the patch marker `TPM_LIBEV_FD_REIFY_PATCH` is missing or another backend is compiled in. `update_ev_c` only re-embeds `ecb.h` and keeps the patch; when importing a newer libev, re-apply it (limited to `backend == EVBACKEND_EPOLL` if other backends are enabled) or drop it together with the check. T14: `epoll_poll()` in `libev/ev_epoll.c` maps EPOLLERR/EPOLLHUP only to the events the fd wants (READ|WRITE when it wants none, so libev's lazy DEL of a mask-0 fd still happens even if the fd reports only EPOLLERR: TCP always adds IN and OUT to ERR/HUP, a UDP socket with a pending ICMP error does not); upstream maps them to both, so an fd waiting only for READ that gets HUP (after our `SHUT_WR`, the peer's FIN) costs an `EPOLL_CTL_MOD` to the mask the kernel already has (for a non-zero mask the kernel registration always equals it, and epoll reports only registered IN/OUT bits). `my_ev.cpp` fails the build if its marker `TPM_LIBEV_EPOLL_HUP_PATCH` is missing; re-apply it when importing a newer libev.
- `docker/`: Build images and `docker/build.sh`, which builds tinymapper inside Linux containers (glibc, musl, their `-assert` variants with `DEBUG_ASSERT` enabled, and a zig-based compile check of the release cross targets) into `build/`.
- `tests/`: Go functional test suite (own `go.mod`, standard library only) and `tests/run.sh`, which runs it inside `ubuntu:24.04` (glibc-assert build) and `alpine:3.22` (musl-assert build) containers.
- `bench/`: Loopback benchmark (`run.sh`), host-mode benchmark over ssh (`host.sh`), syscall counting (`syscount.sh`), perf profiling (`prof/`), the Go load tool (`fwdbench/`), and the recorded baselines (`BASELINE.md`).
- `build/` and `bench/results/`: Generated binaries and benchmark results; both are git-ignored.

## Development Commands

```sh
make all        # Native Linux build: ./tinymapper, static, -O2, -lrt (no NDEBUG: libev asserts stay on, X1)
make fast       # Faster debug-style local build, no -O2/static, DEBUG_ASSERT on
make debug      # Debug build with -D MY_DEBUG and -ggdb, DEBUG_ASSERT on
make clean      # Remove generated binaries and git_version.h
make release    # Cross-build configured TARGETS and package tar.gz
make test       # tests/run.sh: build in containers, run the Go functional tests (glibc-assert + musl-assert; the release builds are compiled, not run)
make bench      # bench/run.sh: loopback benchmark + syscall counts, results in bench/results/<stamp>/
```

Container builds (any machine with Docker, including macOS):

```sh
docker/build.sh                  # build/tinymapper-glibc and build/tinymapper-musl
docker/build.sh glibc-assert musl-assert  # same with -DENABLE_DEBUG_ASSERT: build/tinymapper-{glibc,musl}-assert (what make test runs)
docker/build.sh cross            # compile check: amd64 x86 arm mips24kc_be mips24kc_le (zig, musl)
REF=4acc876 docker/build.sh      # build a commit: build/tinymapper-{glibc,musl}-4acc876
```

Run examples:

```sh
./tinymapper -l0.0.0.0:1234 -r10.222.2.1:443 -t -u
./tinymapper -l[::]:1234 -r[2001:19f0:7001:1111:00:ff:11:22]:443 -t -u
./tinymapper -c mapper.toml
```

- `git_version.h` is generated by the `git_version` make target and included by `main.cpp`.
- Cross-compiler paths in `makefile` are hardcoded to the original author's toolchain locations; expect to override variables or use local targets.
- No `make test`, lint, format, or CI target is defined.

## Code Conventions & Common Patterns

- Style is pragmatic C-with-classes C++11: global process state, `struct` data holders, `using namespace std`, C socket APIs, `char*`/fixed buffers, and manual lifecycle management.
- Naming is mostly `snake_case`; types commonly end in `_t` (`address_t`, `tcp_pair_t`, `lru_collector_t`). Runtime forwarding state lives in `app_config.rules` and `forward_rules`; each `forward_rule_t` owns its listener fds and TCP/UDP managers.
- Keep networking nonblocking: create sockets with `SOCK_NONBLOCK|SOCK_CLOEXEC` passed to `socket()` / `accept4()` instead of a follow-up `fcntl` (`setnonblocking()`). Use `set_buf_size()` (on TCP sockets only when `sock_buf_explicit`) and `close()`; once a pair exists, its fds are closed only by the managers' `erase()`/`erase_closed()`, after its watchers are stopped.
- Logging: `mylog(level, ...)` checks the level before calling `log0()`, so arguments of filtered messages are not evaluated; `log0()` itself does not check `log_level`. `mylog_unfiltered(level, ...)` skips the check except at `--log-level 0`; only the SIGUSR1 stats use it (D26). `log0()` is declared with `__attribute__((format(printf,5,6)))`, so `-Wformat` checks every `mylog` call. It formats the whole line into a stack buffer and writes it with one `fwrite` (the timestamp and each level's `color[time][LEVEL]` prefix are formatted once per second into unlocked function-local statics, so only the event-loop thread may log: the DNS worker hands errors back through `dns_result_cb()`; the timestamp uses `localtime_r` because glibc's `localtime()` re-checks `/etc/localtime` on every call; `enable_log_color` is not part of the cache key, so it must not change once `log0()` has run: only the pre-scan at the top of `process_arg()` sets it, and the one earlier `log0()` call, the `ev_default_loop()` failure in `main()`, exits immediately). stdout is flushed per line only on a tty; otherwise it stays fully buffered (4 KiB with glibc, 1 KiB with musl) and is written when the buffer fills, by `clear_timer_cb()` every `timer_interval` (400 ms), and by `myexit()`, so lines written right before an abort, an unhandled signal, or SIGKILL can be lost.
- Addresses: connections keep the client address as `address_t` (`tcp_pair_t::addr`, `udp_pair_t::adress`) and format it only inside `mylog` arguments with `get_str()`, so filtered lines and the per-packet UDP path do no formatting. `get_str()` returns one static buffer: use it at most once per `mylog` call and only on the event-loop thread; otherwise `to_str()` into a local `char[max_addr_len]`. `to_str()` hand-formats IPv4, v4-mapped IPv6 (`::ffff:a.b.c.d`, how IPv4 clients of a dual-stack `[::]` listener appear) and the port (no `sprintf`); other IPv6 goes through `inet_ntop`. `to_str()` must not change `errno`: a `mylog` call may evaluate `get_str()` before `get_sock_error()`.
- Error handling uses `mylog(level, ...)`, `myexit()`, and `assert()` for invariants. Invariants checked per event, per packet or per connection (the callbacks, `tcp_accept_one()`, `select_remote_index()`, `lru_collector_t`, the managers' `erase()`, `address_t::get_len()`/`from_sockaddr()`/`to_str()`) use `DEBUG_ASSERT()` (`common.h`): `assert()` only when `ENABLE_DEBUG_ASSERT` is defined (`make all OPT=-DENABLE_DEBUG_ASSERT`, i.e. the `-assert` builds that `make test` runs, and `make fast`/`make debug`), otherwise `((void)sizeof(!(x)))`, so `make all` and `make release` compile them out. The expression must have no side effects (release builds do not evaluate it, and no compiler warns) and no lambda. Use it only for internal invariants, never to validate input: in a release build a violated check is undefined behaviour instead of an abort, either a crash without a message (e.g. `erase(end())` in the UDP manager) or silent corruption (a leaked block and lost data in `tcp_cb()`, cross-talk between pairs). `ENABLE_DEBUG_ASSERT` together with `NDEBUG` is a `#error`, because it would silently drop every assert; zig defines `NDEBUG` at `-O1` and above, so the `docker/build.sh cross` compile check builds no asserts at all. Release builds (`make all`, `make release`) deliberately do not define `NDEBUG` (X1, D28): after T12 that would only remove libev's checks (nothing measurable on any workload), and without libev's `corrupted watcher` assertion a missing `ev_io_stop()` whose pair and fd number are reused turns from an abort into a livelock (`fd_reify()` walks a looped watcher list forever: 100% CPU, SIGTERM never handled, the process does not exit). Do not add `NDEBUG` to `FLAGS` or the release targets; a release built with zig needs `-UNDEBUG`. Startup and config checks keep plain `assert()`. Fatal setup errors usually log `log_fatal` then exit; runtime network errors usually log and close/erase the affected connection. `myexit()` flushes stdout and calls `_exit()`: no static destructors or `atexit` handlers run, because the detached DNS thread may still be blocked on `dns_cv` (glibc's `pthread_cond_destroy` would wait for it forever), so do not put shutdown work in destructors.
- Async work is libev-based only: `ev_io_init/start/stop`, `ev_timer`, `ev_signal`, `EV_READ`, and `EV_WRITE`. When changing watcher events on the same fd, existing code stops the watcher, changes `events` (no `ev_io_init`, T13), then restarts it.
- Avoid introducing new allocation-heavy abstractions in hot paths. TCP data goes through `tcp_scratch` and `tcp_buf_pool` blocks and connection objects through `obj_pool_t`, so TCP forwarding and TCP connection setup do not call `malloc()` once the pools have grown to the peak (free blocks beyond 64 are freed and allocated again in the next backpressure burst); a new UDP session still allocates one `adress_to_info` node. UDP uses stack buffers in callbacks.
- `libev/ev_wrap.h` is generated by `libev/update_ev_wrap`; do not hand-edit generated or vendored libev files unless the change is explicitly about the embedded event loop.

## Important Files

- `main.cpp`: Entry point, CLI/config selection, protocol callbacks, event loop, per-rule runtime, connection managers, connection-object and TCP buffer pools.
- `config.h` / `config.cpp`: Minimal TOML subset parser for `[network]` defaults and `[[endpoints]]` forwarding rules.
- `common.h` / `common.cpp`: Shared types, `address_t` parsing/formatting, time helpers, socket helpers.
- `log.h` / `log.cpp`: Logging levels, color/position flags, `mylog()` / `log0()` implementation.
- `my_ev_common.h`: Embedded libev configuration (`EV_STANDALONE`, `EV_COMMON` = `void *data;`, `EV_COMPAT3`) and the epoll-only backend selection (`EV_USE_EPOLL`/`EV_USE_EVENTFD` on, `EV_USE_POLL`/`EV_USE_SELECT` off) for both glibc and musl.
- `my_ev.h` / `my_ev.cpp`: Libev include wrapper and direct `#include "ev.c"` compilation unit, plus `my_ev_mono_now()` (libev 4.24 has no public accessor for the loop's cached monotonic time; `ev_now()` is the wall-clock `ev_rt_now`).
- `makefile`: Build, cross-build, release, cleanup, and the `test` / `bench` entry points.
- `README.md`: User-facing usage examples, options, supported platforms, and performance-test reference.
- `libev/update_ev_wrap`, `libev/update_ev_c`, `libev/update_symbols`, `libev/import_libevent`: Vendored libev maintenance helpers.

## Runtime/Tooling Preferences

- Required language/toolchain: C++11 with `g++`/compatible compiler and GNU Make-style `makefile`.
- No Node, Bun, Python package manager, or dependency lockfile is used for the project build. Go (tests, `bench/fwdbench`) and Python 3 (bench summaries) use only their standard libraries.
- libev is always embedded (`my_ev.cpp` includes `ev.c`) and built with the epoll backend only; `event_loop()` logs the active backend (`event backend: epoll`) at startup.
- Linux is the only supported platform (glibc distributions and OpenWRT/musl; deployed directly on hosts). Windows/macOS/FreeBSD/Cygwin targets and code paths were removed; do not add non-Linux fallbacks. On a macOS dev machine, build and test through `docker/build.sh` / `make test`.
- Keep `libev/` treated as third-party vendored code. Prefer changing project wrapper/configuration files before modifying libev internals; the only local changes that affect Linux builds are the `fd_reify()` patch (T13) and the `epoll_poll()` ERR/HUP mapping (T14).

## Testing & QA

- Functional tests: `make test` (= `tests/run.sh`) builds tinymapper with `docker/build.sh`, cross-compiles the Go test binary on the host (`GOOS=linux`), and runs it in `ubuntu:24.04` against the glibc-assert build and in `alpine:3.22` against the musl-assert build (`--network none`, loopback only; the `-assert` builds differ from `make all` only by `-DENABLE_DEBUG_ASSERT`, D20; the matching release builds are compiled too but not run, D22, and a working-tree `-assert` binary that lacks the hot-path assert strings is rejected). Useful knobs: `VARIANTS=glibc-assert` (one libc), `VARIANTS="glibc musl"` (the release builds, without `DEBUG_ASSERT`), `REF=<commit>` (test a commit's build, `build/tinymapper-<variant>-<commit>`), `TPM_NO_BUILD=1`, `TPM_SLOW=1` (adds the ~6 min TCP/UDP idle-timeout tests and the ~2 min upstream connect-timeout test, run in parallel), and test-binary flags such as `-test.run X -test.v`.
- Coverage: TCP integrity (1 B–1 GiB, 100/5000 concurrent), TCP semantics (half-close from either side, with a pending reverse backlog, and before the upstream connect completes; RST, refused/unreachable upstream, server-first; upstream connect result: client data (256 KiB, more than one buffer) or EOF held while connecting, a streaming upstream not starving the held request, refusal after held data or half-close, kernel SYN timeout; - The `obj_pool_t::put()` watcher check (D30) cannot be triggered from outside, so the suite only shows it never fires on correct code; it was verified with lifecycle mutants (a missing `ev_io_stop()`, freeing before stopping), which all abort with its `log_fatal` line in release builds.
- Known defects are wrapped in `xfail(t, "<id>", ...)` with IDs from the optimization roadmap (none at present). The body asserts the correct behavior; once a fix lands the test reports XPASS and fails until the `xfail` wrapper is removed.
- Listener readiness (`listening()`/`listenFD()`), the accept-queue length in `listenFull` and the SYN_SENT count in `synSentTo` come from `NETLINK_SOCK_DIAG` queries, never from reading `/proc/net/tcp`: next to `TestTCPMaxConn` (about 80k sockets) one read of that file takes seconds and readiness waits time out.
- Tests that edit `/etc/hosts` only run when `TPM_IN_CONTAINER=1` (set by `tests/run.sh`); never run them on a real host.
- Benchmarks: `make bench` (= `bench/run.sh`) runs the loopback benchmark and syscall counts in Docker (forwarder CPU0, client CPU2-3, backends CPU4-5) and writes `bench/results/<stamp>/`. `FWDS="tinymapper@4acc876 tinymapper" bench/run.sh` compares a commit with the working tree; `QUICK=1` is a smoke run; `bench/host.sh` runs the same workloads on real client/forwarder/server hosts over ssh. Run benchmarks with the Docker VM otherwise idle. Baselines and procedures are in `bench/BASELINE.md`.
- For source changes, at minimum run `make test`; for data-path changes also compare benchmarks and syscall counts against the baseline.
